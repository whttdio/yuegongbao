# 粤工保 / 安责保双前端研发批次与验收任务书

日期：2026-06-05

## 1. 文档目的

这份任务书不再讨论方向，只用于排期、开发、联调和验收。

它只回答四个问题：

1. 先做什么
2. 前端改什么
3. 后端补什么
4. 验收按什么标准过

## 3. 固定实施原则

### 3.1 后端原则

- 统一主数据
- 统一状态机
- 统一权限校验
- 统一 CRUD
- 优先补聚合接口，不复制业务表

固定要求：

- 不新建“粤工保后台”和“安责保后台”两套服务
- 共享模块只补 `summary/dashboard/detail-hint`
- 门户差异通过聚合层和菜单权限表达

### 3.2 前端原则

- `ygb` 不是默认后台壳，必须是办理工作台
- `azb` 不是换皮频道，必须是治理工作台
- 共享模块必须拆成双视图
- 高频页必须有“摘要 + 当前对象 + 推荐动作 + 详情联动”

### 3.3 测试原则

- 不按页面单测验收
- 按 `角色 + 门户 + 模块 + 动作` 四维验收

## 4. 研发批次

## 4.1 P0 立即执行批：把 `ygb` 剩余主链补成可用工作台

### 目标

把还停留在基础 CRUD 的人社整改、财务整改、专项治理页升级成高频工作台。

### 页面范围

| 页面目录 | 当前问题 | 本批目标 |
| --- | --- | --- |
| `views/ygb/taxCompare` | 仍偏表单 + 表格 | 改成个税比对整改台账 |
| `views/ygb/employmentRatio` | 缺少重点企业队列 | 改成用工比例合规台账 |
| `views/ygb/fakeOutsourcing` | 缺少疑似对象优先级 | 改成假外包识别复核台账 |
| `views/ygb/newformWorker` | 缺少重点对象摘要 | 改成新业态人员监管台账 |
| `views/ygb/occupationMonitor` | 缺少区域聚合 | 改成职业病监测台账 |

### 后端动作

1. 为上述模块补 `summary` 聚合接口
2. 首页补财务整改和专项治理摘要队列
3. 校对企业角色与监管角色的按钮边界

### 前端固定结构

每页统一按下面结构做：

1. 顶部业务定位
2. 摘要卡
3. 办理焦点
4. 当前选中对象
5. 推荐办理动作
6. 搜索区
7. 工具栏
8. 表格
9. 详情抽屉

### 验收标准

1. 企业管理员进入页面 3 秒内能看到当前待办对象
2. 摘要来自后端聚合，不从当前页列表临时拼
3. 行点击后能联动当前对象与详情抽屉
4. `vite build --mode ygb` 可通过

## 8. 最终执行结论

1. 这个项目不是“一个后台两个登录页”，而是“一个后台、两个长期业务门户”。
2. 对于共享模块，后台统一是成本优势，前端双语义是效率要求，这两件事必须同时成立。
3. 短期开发优先级应先补 `ygb` 剩余主链工作台，再收口 `azb` 剩余治理页，再接评分体系。
4. 后续排期、派工、联调、验收都应按本任务书推进，不再以“基础 CRUD 是否有了”作为完成标准。
