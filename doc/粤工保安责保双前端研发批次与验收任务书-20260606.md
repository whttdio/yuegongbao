# 粤工保安责保双前端研发批次与验收任务书

在不拆后台、不复制主数据、不新增第二套核心业务表的前提下，把当前仓库推进到可持续交付状态：

- 两个登录入口稳定
- 两个门户菜单稳定
- 两个首页工作台稳定
- 一套后台对象单源
- 一套共享业务逻辑
- 两套明确不同的前端工作流表达

## 3. 研发批次

## P1 门户与角色矩阵固化

### 目标

把“谁默认进哪个门户、谁看到哪些菜单、谁只能只读”做成正式验收项。

### 涉及范围

- `src/config/portal.js`
- `src/utils/portal.js`
- `src/permission.js`
- `src/store/modules/permission.js`
- 角色/菜单 SQL 注入结果

### 必测角色

- `104 ygb_enterprise_admin`
- `105 ygb_enterprise_operator`
- `106 ygb_hrss_supervisor`
- `107 ygb_emergency_supervisor`
- `108 ygb_insurer`
- `109 ygb_bank`

### 验收标准

1. 默认门户正确。
2. 访问错误门户能自动回跳或受控进入。
3. 只显示当前门户可见菜单。
4. 只显示当前角色允许动作。
5. `108/109` 不出现维护、处置、录入类按钮。

## P2 首页工作台高频化

### 目标

让首页从“统计展示页”升级为“高频工作台”。

### 涉及范围

- `src/views/index.vue`
- `src/views/homeWorkbenchConfig.js`
- `src/views/home/*`

### `ygb` 目标态

- 首屏前置合同、考勤、工资、社保、高处作业
- 财务链成组展示
- 监管链保留驾驶舱、预警、统计
- 首页队列可直接带条件下钻

### `azb` 目标态

- 首屏前置驾驶舱、预警中心、设备、高处作业、安责险
- 保险/银行角色只保留轻视图工作台
- 企业角色进入 `azb` 后切换为现场治理视角

### 验收标准

1. `ygb` 首页看起来是办理工作台，不是监管总览页。
2. `azb` 首页看起来是治理工作台，不是企业录入页。
3. 首页重点队列能直接跳到目标页并保留筛选上下文。
4. 只读角色首页不会暴露复杂治理入口。

## P3 共享模块去同质化

### 目标

把共享模块从“两个页面长得差不多”升级成“同底数双视图”。

### 优先模块

1. `enterprise`
2. `person`
3. `warning`
4. `device`
5. `aqInsurance`
6. `heightWorkReport`
7. `creditScore`
8. `statReport`
9. `cockpit`

### 每个模块必须具备

- 首屏摘要
- 重点对象或焦点队列
- 当前对象摘要区
- 推荐动作区
- 详情重点字段分组
- 只读角色动作收口
- 工作台来源回链

### 验收标准

1. 同一对象在 `ygb/azb` 首屏摘要不同。
2. 同一对象在 `ygb/azb` 推荐动作顺序不同。
3. 同一对象在 `ygb/azb` 详情重点字段不同。
4. 页面文案不再混用人社与应急语义。

## P4 高处作业与技术防范产品化

### 目标

把高处作业从“已上模块”继续做成双门户都真能用的共享能力。

### 涉及范围

- `heightWorkReport`
- `warning`
- `device`
- `aiReport`

### `ygb` 目标态

- 企业报备闭环
- 作业结束登记
- 证书结果可见
- 凭证留痕可查

### `azb` 目标态

- 在途高危作业队列
- 证书异常与未结束对象优先
- 区域风险分布
- 与预警和设备联动

### 验收标准

1. 企业角色能在 `ygb` 完成完整报备闭环。
2. 监管角色能在 `azb` 快速锁定在途和异常对象。
3. 同一报备单在双门户数据不分叉。
4. 详情、结束、凭证、预警联动链路完整。

## P5 530.1 与 6.1 指标解释挂接

### 目标

把 530.1 与 6.1 从“文档依据”变成“页面解释口径”。

### 后端工作

- 评分维度配置
- 得分点配置
- 权重配置
- 阈值配置
- 企业快照
- 区域快照
- 门户聚合解释接口

### 前端工作

`ygb` 挂接：

- 劳务合规
- 工伤预防
- 扩面减损
- 财务整改

`azb` 挂接：

- 安责险覆盖
- 设备安全
- 技术防范
- AI 风险识别
- 区域治理成效

### 验收标准

1. 同一企业在 `ygb/azb` 可看到不同排序的解释结果。
2. 每个得分点可追溯到业务对象或聚合指标。
3. 调整权重无需改页面代码。
4. 首页、驾驶舱、报表页均能下钻解释。

## P6 全链路回归

### 目标

按“角色 + 门户 + 模块 + 动作”回归，不再只测 CRUD。

### 必测模块

- `home`
- `cockpit`
- `enterprise`
- `person`
- `warning`
- `warningRule`
- `device`
- `aqInsurance`
- `heightWorkReport`
- `aiReport`
- `creditScore`
- `statReport`
- `uninsuredList`
- `preventionFund`

### 每模块最少回归动作

- 列表
- 查询
- 详情
- 导出
- 新增或编辑
- 结束或处置
- 只读收口

### 验收标准

1. 菜单显隐与角色矩阵一致。
2. 按钮显隐与角色矩阵一致。
3. 共用数据在双门户之间保持同源。
4. 双门户首屏表达和优先动作不同。
5. `ygb/azb` 双构建通过。

## 4. 派工规则

### 前端

- 共享逻辑优先改 `useXxxPage.js`、工具、API 封装
- 门户差异优先改 `src/views/ygb/*` 与 `src/views/azb/*`
- 首页与回链逻辑统一收口到 `index.vue`、`homeWorkbenchConfig.js`、`workbenchLink.js`

### 后端

- 任何共享对象禁止按门户复制业务表
- 任何共享模块禁止再开第二套门户专用接口主链
- 门户差异优先通过聚合接口、摘要接口、配置项解决

### 测试

- 以“角色-门户-场景”组织用例
- 每个高频角色至少覆盖一个完整业务闭环
- 只读角色单独做动作收口回归

## 5. 页面完成标准

后续页面不再以“有表能查”作为完成标准，统一按以下标准验收：

1. 首屏有清晰摘要。
2. 有重点对象或焦点队列。
3. 有当前对象摘要区。
4. 有推荐动作区。
5. 详情页有重点字段分组。
6. 只读角色自动收口动作。
7. 双门户首屏表达明显不同。

## 6. 技术门槛

每一批提交前必须满足：

1. `ygb` 构建通过。
2. `azb` 构建通过。
3. 共享对象仍为单源。
4. 门户菜单过滤正常。
5. 默认门户与错门户回跳正常。
6. 只读角色动作收口正常。

## 7. 推荐执行顺序

建议按以下顺序推进：

1. P1 门户与角色矩阵固化
2. P2 首页工作台高频化
3. P3 共享模块去同质化
4. P4 高处作业与技术防范产品化
5. P5 530.1 与 6.1 指标解释挂接
6. P6 全链路回归

原因很直接：

- 先把入口和角色边界定稳
- 再把高频使用路径做顺
- 最后再挂评分解释和大回归
