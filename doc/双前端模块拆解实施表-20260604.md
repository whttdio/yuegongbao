# 双前端模块拆解实施表

## 1. 使用方式

这份表不是概念方案，而是给产品、前端、后端、测试直接排期和验收用。

- 后端先判断：`共后台`、`ygb 独占`、`azb 独立视图`
- 前端再判断：是否必须拆成 `views/ygb` 与 `views/azb` 两套页面
- 接口层统一原则：`CRUD 共用，summary/dashboard 按门户补`

判断依据沿用：

- `530.1` 需求分析说明书
- `评分体系 6.1`
- 当前仓库双前端底座与已完成改造页

## 3. 明确不拆两套后台的边界

以下内容继续只保留一套后台内核，不再复制第二套业务表：

- 企业、人员、设备、预警、高处作业、工伤、安责险、AI、信用、统计底数
- 状态机与基础 CRUD
- 文件上传、导出、导入、通用字典、权限校验

只有这些内容允许按门户分开：

- 登录页与首页
- 菜单树与按钮显隐
- 摘要卡片
- 默认筛选
- 页面说明文案
- 详情抽屉重点
- 首页快捷入口与待办队列

## 5. 模块级开发规则

每个共享模块在实施时都按下面顺序落地：

1. 先判断是不是 `ygb 独占` 或 `双视图`
2. 若是双视图，先确认 `ygb` 和 `azb` 的首要动作是否不同
3. 首要动作不同，直接拆 `views/ygb` 与 `views/azb`
4. 后端不复制 CRUD，只补轻量 `summary/dashboard`
5. 只读角色先在前端显式收口，再由后端权限二次兜底

## 6. 验收标准

### 6.1 模块拆解正确

- 同一模块的数据源仍是一套
- 两个门户的首页入口、摘要和详情重点明显不同
- `ygb` 不再承载安责保治理语义
- `azb` 不再承载企业劳务办理主链

### 6.2 页面升级正确

- 不再只展示基础表格
- 摘要卡全部来自后端聚合，不从分页列表临时计算
- 行点击可联动当前对象和详情抽屉
- 详情中能直接看到“下一步做什么”

### 6.3 权限收口正确

- `ygb` 独占模块在 `azb` 不可见
- 只读角色只保留查询、详情、导出
- 高风险治理按钮只向办理角色开放
