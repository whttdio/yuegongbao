# 双前端模块归属与双视图拆解定案

## 1. 结论先行

粤工保和安责保不能继续按“同一套后台页面换两个登录页”理解，必须固定为：

- 一套后台内核
- 两个前端门户
- 一套主数据和业务状态
- 两套长期独立的工作台表达

结合 `粤工保开发需求分析说明书（530.1版）` 与 `粤工保与安责保平台评分体系细化得分点6.1`，最终边界应固定为：

- `ygb` 承接企业办理、人社监管、财务整改主链
- `azb` 承接应急监管、现场治理、安责险协同主链
- 共性模块共享数据和 CRUD，不再强行共页面

## 2. “七成共性”在工程上的真实含义

“七成内容一样”只能理解成下面三层共性，不等于七成页面完全一样。

### 2.1 数据共性

必须共用，不应拆库：

- 企业主数据
- 人员主数据
- 设备台账
- 预警工单
- 高处作业报备
- 工伤事件
- 安责险保单
- AI 识别结果
- 信用评分结果
- 统计报表底数

### 2.2 业务内核共性

原则上也只保留一套：

- CRUD
- 状态机
- 导入导出
- 文件上传
- 字典枚举
- 权限底座
- 外部系统 Stub 或正式接口

### 2.3 页面表达差异

这部分不能再按“共性”处理，必须按门户拆开：

- 登录页
- 首页工作台
- 菜单树
- 摘要卡
- 默认筛选
- 详情重点
- 按钮密度
- 推荐办理路径
- 快捷入口

结论：

- `共后台` 可以很高
- `共页面` 不应再高

## 3. 双门户的长期职责边界

### 3.1 粤工保 `ygb`

固定定位：

- 企业办理工作台
- 人社监管工作台
- 财务整改工作台

长期核心语义：

- 办理
- 归集
- 整改
- 对账
- 归档
- 闭环

### 3.2 安责保 `azb`

固定定位：

- 应急治理工作台
- 安责险协同工作台
- 风险处置工作台

长期核心语义：

- 风险
- 治理
- 处置
- 时效
- 在途
- 重点对象

## 4. 模块是否需要双视图的判定标准

任一模块命中以下任意 2 条，就必须按 `ygb/azb` 双视图处理：

1. 两边主要使用角色不同
2. 两边首要动作不同
3. 两边统计口径不同
4. 两边首页入口优先级不同
5. 两边详情页关注重点不同
6. 两边默认按钮密度不同

只有命中 0 到 1 条，才允许继续共页面或轻包装。

## 6. 两个监管部门重叠内容的拆法

监管重叠不代表入口、详情和动作可以相同。固定拆法如下。

### 6.1 同对象，不同入口

这类模块：

- 单位管理
- 人员管理
- 预警中心
- 工伤事件
- 高处作业
- 统计报表
- AI 报告

处理方式：

- 后台共对象
- `ygb` 从办理链进入
- `azb` 从风险对象进入

### 6.2 同数据，不同行动

典型例子：

- 高处作业
  - `ygb` 先看是否已报备、是否可结束、是否缺材料
  - `azb` 先看进行中、异常证书、重点区域、超时未结束
- 设备管理
  - `ygb` 先看授权、接入、回写异常
  - `azb` 先看离线、锁机失败、围栏越界、AI 异常
- 预警中心
  - `ygb` 先看与工资、社保、合同、高处作业关联的待处理事项
  - `azb` 先看红警、重大隐患、重复预警、处置时效

结论：

- 重叠不代表入口一样
- 重叠不代表详情一样
- 重叠不代表按钮一样

## 7. 评分体系与门户主链映射

### 7.1 粤工保 `ygb`

`6.1` 里粤工保侧主评分链应固定映射到：

| 评分维度 | 主落点模块 | 页面目标 |
| --- | --- | --- |
| 工伤预防 | 工伤事件、预防项目、预防资金池、统计报表 | 看下降趋势与归档完成率 |
| 用工合规 | 合同、考勤、工资、社保、个税、用工比例、假外包 | 看办理闭环与整改完成率 |
| 设备安全 | 设备、预警 | 看异常处理和企业整改 |
| 参保扩面 | 社保、安责险、漏保清单 | 看扩面进度与漏保回补 |
| 预警处置 | 预警中心、预警规则 | 看待办和闭环率 |
| 技术防范 | 高处作业、AI 报告、设备、预警 | 看报备留痕和异常压降 |

### 7.2 安责保 `azb`

`6.1` 里安责保侧主评分链应固定映射到：

| 评分维度 | 主落点模块 | 页面目标 |
| --- | --- | --- |
| 安责险合规 | 安责险、预防资金池、预防项目 | 看保单覆盖、资金健康、项目成效 |
| 设备安全 | 设备、预警、工伤事件 | 看在线率、离线时长、处置效率 |
| 技术防范 | 高处作业、AI 报告、设备、预警 | 看高危作业、识别结果、压降时效 |
| 隐患整改 | 预警中心、AI 报告、设备 | 看风险对象是否压降 |
| 预警处置 | 预警中心、驾驶舱、统计报表 | 看红警、重大隐患、区域态势 |

## 8. 角色归位与默认门户

| 角色 | 默认门户 | 长期主入口 | 页面策略 |
| --- | --- | --- | --- |
| `104 ygb_enterprise_admin` | `ygb` | 合同、考勤、工资、预警、高处作业 | 重办理、重闭环 |
| `105 ygb_enterprise_operator` | `ygb` | 待录入、待修改、待结束 | 少噪音、强校验 |
| `106 ygb_hrss_supervisor` | `ygb` | 区域态势、整改对象、统计归档 | 重监管汇总 |
| `107 ygb_emergency_supervisor` | `azb` | 红警、设备、高危作业、AI 风险 | 重治理、重处置 |
| `108 ygb_insurer` | `azb` | 保单、资金池、信用、报表 | 只读协同轻视图 |
| `109 ygb_bank` | `azb` | 工资风险摘要、信用、报表 | 只读协同轻视图 |

执行规则：

1. `104/105/106` 进入系统默认落到 `ygb`
2. `107/108/109` 进入系统默认落到 `azb`
3. `108/109` 只保留摘要、详情、导出，不进入复杂维护页
4. `ygb` 不再承载安责保治理主语义
5. `azb` 不再承载企业劳务办理主链

## 9. 页面设计固定规则

### 9.1 `ygb` 页面结构

所有高频页固定按下面结构升级：

1. 顶部业务定位
2. 摘要卡
3. 办理焦点
4. 当前选中对象
5. 办理路径
6. 搜索区
7. 工具栏
8. 台账表格
9. 详情抽屉

### 9.2 `azb` 页面结构

所有高频页固定按下面结构升级：

1. 顶部治理定位
2. 摘要卡
3. 焦点队列
4. 当前风险对象
5. 风险提示
6. 搜索区
7. 工具栏
8. 治理台账
9. 详情抽屉

## 10. 最终定案

1. 双前端方案继续成立，而且已经从概念讨论进入实施阶段。
2. 后端不拆两套业务库，继续走 `共内核 + 门户聚合 + 双视图`。
3. `ygb` 负责企业办理和人社监管主链，`azb` 负责风险治理和应急协同主链。
4. 后续所有新模块都先按本定案判归属，再决定是否同步开发双视图。
