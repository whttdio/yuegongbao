日期：2026-06-06

## 1. 目标

在不拆后台、不复制主数据、不新增第二套核心业务表的前提下，把当前仓库推进到可持续交付状态：

- 两个登录入口稳定
- 两个门户菜单稳定
- 两个首页工作台稳定
- 一套后台对象单源
- 一套共享业务逻辑
- 两套明确不同的前端工作流表达

这份清单用于直接派工、排批次、定验收，不再停留在“是否双前端”的讨论。

## 3. 批次规划

## P1. 门户与角色矩阵固化

### 目标

把“谁默认进哪个门户、谁看到哪些菜单、谁只能只读”做成正式验收项。

### 改造范围

- 门户配置与默认入口
- 登录后跳转规则
- 错门户访问回跳规则
- 角色菜单显隐
- 只读角色动作收口

### 涉及代码

- [yuegongbao-ui/src/config/portal.js](/D:/javaproject/yuegongbao/YueGongBao-Vue/yuegongbao-ui/src/config/portal.js)
- [yuegongbao-ui/src/utils/portal.js](/D:/javaproject/yuegongbao/YueGongBao-Vue/yuegongbao-ui/src/utils/portal.js)
- [yuegongbao-ui/src/permission.js](/D:/javaproject/yuegongbao/YueGongBao-Vue/yuegongbao-ui/src/permission.js)
- [yuegongbao-ui/src/store/modules/permission.js](/D:/javaproject/yuegongbao/YueGongBao-Vue/yuegongbao-ui/src/store/modules/permission.js)

### 必测角色

- `104 ygb_enterprise_admin`
- `105 ygb_enterprise_operator`

### 验收点

1. 登录后默认进入正确门户。
2. 访问错门户直链时自动回跳。
3. 当前门户只显示当前门户可见菜单。
4. 只显示当前角色允许动作。
5. `108/109` 不出现录入、整改、治理类按钮。

## P2. 首页工作台高频化

### 目标

把首页从普通统计页升级成真实工作台。

### `ygb` 必须做到

- 首页先给企业高频办理入口，不先讲平台概念
- 把合同、考勤、工资、社保、高处作业、预警整改前置
- 把财务链做成成组入口
- 首页重点队列能带着筛选条件跳到目标页

### `azb` 必须做到

- 首页先给区域风险、设备、预警、高处作业、安责险入口
- 首页先看风险对象，不先看基础台账
- 保险公司、银行角色保留轻量只读工作台
- 首页重点队列能带着风险上下文跳到目标页

### 涉及代码

- [yuegongbao-ui/src/views/index.vue](/D:/javaproject/yuegongbao/YueGongBao-Vue/yuegongbao-ui/src/views/index.vue)
- [yuegongbao-ui/src/views/homeWorkbenchConfig.js](/D:/javaproject/yuegongbao/YueGongBao-Vue/yuegongbao-ui/src/views/homeWorkbenchConfig.js)
- [yuegongbao-ui/src/utils/workbenchLink.js](/D:/javaproject/yuegongbao/YueGongBao-Vue/yuegongbao-ui/src/utils/workbenchLink.js)

### 验收点

1. `ygb` 首页看起来像办理工作台，不是监管概览页。
2. `azb` 首页看起来像治理工作台，不是企业录入页。
3. 同一对象在双门户首页的摘要、标签、动作顺序明显不同。
4. 首页重点队列不是静态卡片，而是可下钻的真实入口。

## P3. 共享模块去同质化

### 目标

把已经做成双外壳的共享模块继续拆深，不停留在“标题不同、表格一样”。

### 优先模块

1. `enterprise`
2. `person`
3. `warning`
4. `device`
5. `aqInsurance`
6. `heightWorkReport`
7. `injuryEvent`
8. `creditScore`
9. `statReport`
10. `cockpit`

### 每个模块必须补齐的能力

- 首屏摘要卡
- 重点对象或焦点队列
- 当前选中对象摘要
- 推荐动作区
- 详情重点字段分组
- 只读角色动作收口
- 工作台来源承接与清空

### 验收点

1. 详情页首屏信息块双端不再同质。
2. 列表页筛选条件能体现门户语义差异。
3. 同一条数据在双端的推荐动作排序不同。
4. 页面文案不再混用人社和应急语义。

## P4. 高处作业与技术防范产品化

### 目标

把高处作业模块从“已上线一个模块”升级成双门户都能高频使用的共享能力。

### `ygb` 侧要求

- 强调企业报备
- 强调作业结束
- 强调凭证留痕
- 强调现场填报闭环

### `azb` 侧要求

- 强调在途作业
- 强调证书异常
- 强调区域分布
- 强调监管闭环

### 联动要求

- 与预警中心联动
- 与设备管理联动
- 与 AI 报告联动
- 与企业、人员台账联动

### 验收点

1. 企业角色在 `ygb` 可顺畅完成报备闭环。
2. 监管角色在 `azb` 可快速锁定在途高危作业对象。
3. 详情、结束、凭证、告警联动路径完整。
4. 同一报备单在双门户不存在数据分叉。

## P5. 530.1 与 6.1 评分解释挂接

### 目标

把共享业务底数与双门户评分解释正式接起来。

### 后端工作

- 评分维度配置
- 得分点配置
- 权重配置
- 阈值配置
- 月度聚合任务
- 企业评分快照
- 区域评分快照
- 门户解释聚合接口

### 前端工作

`ygb` 解释主题：

- 劳务合规
- 扩面减损
- 工伤预防
- 整改归档

`azb` 解释主题：

- 安责险覆盖
- 设备安全
- 高危作业
- 风险压降
- 区域治理成效

### 验收点

1. 同一企业在 `ygb` 和 `azb` 可看到不同排序的评分解释。
2. 每个得分点都能追溯到源对象或聚合指标。
3. 调整权重不需要改前端页面代码。
4. 评分解释能从首页、驾驶舱、报表页下钻到具体模块。

### 目标

按“角色 + 门户 + 模块 + 动作”做正式回归，不再只验 CRUD。

### 必测模块

### 每模块最低回归动作

- 列表
- 查询
- 详情
- 导出

- 结束或处置
- 只读动作收口

### 验收点

1. 菜单显隐与门户范围一致。
2. 按钮显隐与角色权限一致。
3. 共享数据在双门户之间保持同源。
4. 两个门户的页面重点和主动动作不同。

## 4. 派工规则

### 前端派工

- 共享逻辑优先落到 `useXxxPage.js`、公共工具、API 封装
- 门户差异优先落到 `src/views/ygb/*` 与 `src/views/azb/*`
- 首页相关统一在 `index.vue` 与 `homeWorkbenchConfig.js` 收口

### 后端派工

- 任何共享对象禁止按门户复制表
- 任何共享模块禁止再开第二套门户专用 API 主链
- 门户差异优先通过聚合接口、摘要接口、配置项解决

### 测试派工

- 不按“页面”测，要按“角色-门户-场景”测
- 每个高频角色至少覆盖一个完整工作闭环
- 对只读角色单独做动作收口回归

## 5. 页面完成标准

后续模块不再以“有表能查”作为完成标准，统一按以下标准验收：

1. 首屏有明确摘要。
2. 有重点对象或重点队列。
3. 有当前对象摘要区。
4. 有推荐动作区。
5. 详情有重点字段分组与标签化表达。
6. 只读角色动作自动收口。
7. 双门户首屏表达明显不同。

## 6. 技术完成标准

每一批提交前必须满足：

1. `ygb` 构建通过。
2. `azb` 构建通过。
3. 共享对象仍为单源。
4. 门户菜单过滤正常。
5. 默认门户与错门户回跳正常。
6. 只读角色动作收口正常。

## 7. 推荐执行顺序

建议固定按以下顺序推进：

1. P1 门户与角色矩阵固化
2. P2 首页工作台高频化
3. P3 共享模块去同质化
4. P4 高处作业与技术防范产品化
5. P5 530.1 与 6.1 评分解释挂接
6. P6 全链路回归

原因很直接：

- 先把角色、门户、入口稳定住
- 再把高频用户每天都会用的首页和重点模块做实
- 最后再挂评分解释与正式回归

## 8. 这份文档的用途

这份文档只做两件事：

- 给研发排批次
- 给测试定验收口径

后续如无新的产品边界变化，双前端改造统一以本清单和当前仓库真实实现为准。
