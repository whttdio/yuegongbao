# 三端实施现状与回归清单

更新日期：2026-06-24

## 1. 范围说明

- 本轮按三期拆分持续实施，目标是先完成三端前端改造、接口占位层和可联调闭环。
- 涉及硬件设备的真实验收暂时跳过。
- 所有硬件相关能力当前只保留前端展示、交互流程和后续接口对接点。
- 现阶段以当前仓库内三套前端为准：
  - `yuegongbao-worker-miniapp`
  - `yuegongbao-enterprise-miniapp`
  - `yuegongbao-worker-screen-app`

## 2. 总体现状

### 2.1 劳动者手机端 `yuegongbao-worker-miniapp`

- 保持手机端适配，没有引入服务屏 kiosk 布局。
- 劳动者主链页面保持原移动端交互：
  - 登录
  - 首页
  - 工作台
  - 我的
  - 考勤 / 工资 / 社保 / 个税 / 培训 / 拍照 / 找工作 / 法律咨询 / 投诉举报
- 已新增高危扩展模块：
  - `pages/high-risk/scan-unlock`
  - `pages/high-risk/outwork-apply`
  - `pages/high-risk/certificates`
  - `pages/high-risk/work-records`
- 已新增独立接口占位层：
  - `api/high-risk.js`
- 当前高危扩展页均已切换为：
  - 页面调用独立 service
  - 接口失败自动回退前端 mock 数据
  - 保留后续真实解锁 / 审批 / 证件 / 作业追溯接口接入位

### 2.2 企业手机端 `yuegongbao-enterprise-miniapp`

- 保持手机端适配，没有做服务屏布局改造。
- 企业端已形成单独业务路由：
  - `pages/enterprise/people-manage`
  - `pages/enterprise/device-ledger`
  - `pages/enterprise/salary-confirm`
  - `pages/enterprise/operation-approval`
  - `pages/enterprise/insurance-manage`
  - `pages/enterprise/training-manage`
  - `pages/enterprise/job-publish`
- 已新增独立接口占位层：
  - `api/enterprise.js`
- 上述企业页均已切换为：
  - 页面调用独立 service
  - 请求失败自动回退前端 mock 数据
  - 保留后续企业办理接口、审批接口、设备授权接口和培训/保险/岗位正式接口接入位

### 2.3 用工屏端 `yuegongbao-worker-screen-app`

- 明确按 15.6 寸、1920x1080、竖屏服务屏改造。

  - `pages/standby/index`
  - `pages/login/index`
  - `pages/main/index`

  - `api/screen.js`
- 刷脸登录、主界面摘要、设备管理均已切换为：
  - 页面调用独立 service
  - 接口失败自动回退前端 mock 数据
  - 保留后续真实硬件回调、设备控制、聚合摘要接口接入位

## 6. 仍需人工回归的重点

### 6.1 劳动者手机端

- 工作台高危入口跳转是否正常：
  - 扫码开机
  - 外出作业申请
  - 证件管理
  - 作业记录
- 培训联动是否仍正常：
  - 培训未完成时考勤拦截
  - 培训未完成时工资查询拦截
- 通知、投诉、找工作、合同、简历、工会服务原主链不应被高危扩展破坏

### 6.2 企业手机端

- 首页/工作台到 7 个企业业务页跳转是否正常
- 各业务页按钮是否能正确触发占位提交逻辑
- 页面空态、列表态、按钮禁用态是否正常
- 企业端仍应保持手机端手势和单手操作习惯

### 6.3 用工屏端

- 待机页、刷脸页、主界面、设备管理页首屏是否符合 1920x1080 竖屏
- 考勤、工资、社保、个税、投诉、找工作、岗位地图在服务屏上是否：
  - 信息更饱满
  - 按钮热区足够大
  - 卡片换行合理
  - 不再出现明显手机单列空白感
- 主界面跳转到各业务页是否正常
- 服务屏设备页按钮是否都能触发占位逻辑

## 7. 剩余缺口

### 7.1 功能层剩余缺口

- 真实后端接口尚未全部接通，目前仍以占位 service 为主
- 用工屏硬件相关能力未做真机验收：
  - 摄像头
  - 刷脸识别
  - 设备重启/关机/日志导出
  - 设备授权联动
- 企业端审批、工资确认、岗位发布、设备台账等仍缺真实办理闭环
- 劳动者高危扩展模块仍缺真实扫码、证件审核、作业追溯接口

### 7.2 体验层剩余缺口

- 用工屏业务页当前主要是布局层增强，尚未全部做成服务屏专属视觉语言
- 仍存在部分 `pages.json`、文案、标题的乱码问题
- Sass `@import` 告警尚未清理

## 8. 后续建议执行顺序

1. 先做三端关键入口人工回归
2. 再按接口优先级逐步替换 `api/*.js` 中的占位数据
3. 最后做一轮：
   - 用工屏视觉精修
   - 页面乱码清理
   - Sass `@import` 迁移

## 9. 本轮结论

- 三端拆分方向已经落地，不再混用同一套端形态。
- 用工屏已明确服务屏化。
- 两个手机端保持手机适配。
- 目前三端都已具备“页面可跑、路由可进、接口可替换、构建可过”的前端联调基础。
