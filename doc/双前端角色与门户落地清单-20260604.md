# 双前端角色与门户落地清单

## 1. 使用方式

这份清单用于同时指导：

- 角色菜单授权
- 首页默认入口设计
- 页面按钮收口
- 测试验收

原则只有一条：角色不是“看得到什么菜单”这么简单，而是“进入系统后先处理什么事情”。

## 3. 门户归位规则

### 3.1 `ygb` 主角色

- `104`
- `105`
- `106`
- 企业财务

要求：

- 登录后默认进入 `ygb`
- 首页先看办理链、财务链、监管链
- 不主动暴露安责保治理主菜单

### 3.2 `azb` 主角色

- `107`
- `108`
- `109`
- 工地负责人
- 设备管理员

要求：

- 登录后默认进入 `azb`
- 如果这类角色持 token 访问 `ygb`，前端应自动归位到 `azb`
- 首页先看风险、处置、现场、设备、保单、AI 风险对象

## 5. 按钮收口规则

### 5.1 只读角色统一规则

适用：

- `108`
- `109`

统一保留：

- 查询
- 详情
- 导出
- 报表查看

统一隐藏：

- 新增
- 修改
- 删除
- 结束登记
- 批量导入
- 模拟同步
- 启用停用
- 远程设备指令
- 模型版本维护

### 5.2 企业办理角色规则

适用：

- `104`
- `105`
- 企业财务

统一要求：

- 优先保留批量导入、导出、回写、结束登记
- 不给应急治理专属按钮
- `105` 比 `104` 少高级维护和导出类能力

### 5.3 监管角色规则

适用：

- `106`
- `107`

统一要求：

- 可以查看区域态势、重点对象、详情和导出
- 处置权限只保留在监管链路相关模块
- 不应暴露企业内部财务录入型动作

## 6. 菜单与权限落地规则

### 6.1 `portal_scope`

- `ygb` 独占模块和按钮统一标记 `portal_scope=ygb`
- `azb` 独占模块和按钮统一标记 `portal_scope=azb`
- 双端共用菜单可标记 `both`
- 同一共享模块内的高敏按钮允许进一步按门户拆分

### 6.2 角色字段

- `allowed_portal_scope` 决定角色允许进入哪个门户
- `default_portal_code` 决定默认落地门户
- `107/108/109` 应固定默认 `azb`
- `104/105/106` 应固定默认 `ygb`

### 6.3 角色菜单关系

当前继续使用：

- `sys_role_menu.portal_scope`

本轮要求：

- 保存角色授权时保留未编辑门户的既有关系
- 不允许一次保存覆盖另一门户授权

## 7. 测试验收清单

### 7.1 登录与首页

1. `104/105/106` 登录后进入 `ygb`
2. `107/108/109` 登录后进入 `azb`
3. `107/108/109` 持 token 访问 `ygb` 时自动归位 `azb`
4. 两个门户首页重点对象队列明显不同

### 7.2 菜单显隐

1. `azb` 看不到合同、考勤、社保、个税等 `ygb` 独占主链
2. `ygb` 不默认暴露安责保治理专属主链
3. 共享模块在两端都可见，但页面语义不同

### 7.3 按钮显隐

1. `108/109` 没有新增、修改、结束、同步、设备指令等按钮
2. `104` 拥有高处作业 `query/add/edit/finish/export/voucher`
3. `105` 拥有高处作业 `query/add/edit/finish/voucher`
4. `101/102/103` 若保留联调角色，只补高处作业 `query/export`

### 7.4 页面行为

1. 企业管理员在 `ygb` 可完成合同到工资的办理链
2. 财务进入工资相关页先看到批次状态和失败摘要
3. 工地负责人进入 `azb` 先看到高危作业、设备和预警
4. 保险、银行只读角色不会被复杂录入入口干扰

## 8. 建议直接纳入后续排期

1. 目标库复核 `portal_scope + 角色菜单矩阵`
2. 对所有共享高频页补只读角色前端守卫
3. `ygb` 继续补财务主链工作台
4. `azb` 继续补工地负责人和设备管理员轻量工作台
