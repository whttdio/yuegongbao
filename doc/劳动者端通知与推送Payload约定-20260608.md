# 劳动者端通知与推送 Payload 约定

## 1. 目的

本约定用于统一以下三条链路的落页结构：

- `sys_notice.remark` 站内通知跳转配置
- APP 推送 `payload` 跳转配置
- 劳动者端 `UniApp` 内部统一落页解析逻辑

当前仓库已实现：

- 后端通知列表/详情会解析 `sys_notice.remark`
- 通知详情页支持“去处理”按钮
- APP 侧已支持 `uni.onPushMessage` 点击推送后落页
- 未登录时先暂存跳转目标，登录成功后继续落页

## 2. 统一结构

推荐统一使用以下 JSON 对象：

```json
{
  "jumpPath": "/pages/training/index",
  "jumpQuery": {
    "from": "notice",
    "scene": "month-lock"
  },
  "actionLabel": "去完成培训",
  "sourceLabel": "本月培训未完成提醒"
}
```

兼容字段如下：

- 路径：
  - 推荐 `jumpPath`
  - 兼容 `path`
  - 兼容 `url`
- 查询参数：
  - 推荐 `jumpQuery`
  - 兼容 `query`
  - 兼容 `params`
- 按钮文案：
  - 推荐 `actionLabel`
  - 兼容 `actionText`
  - 兼容 `jumpLabel`
  - 兼容 `label`
- 来源文案：
  - 推荐 `sourceLabel`
  - 兼容 `sourceText`

## 3. 字段规则

### 3.1 `jumpPath`

- 必须是劳动者端内部页面路径
- 当前推荐以 `/pages/**` 开头
- 支持普通页面与 `tabBar` 页面

当前 `tabBar` 固定为：

- `/pages/home/index`
- `/pages/workbench/index`
- `/pages/profile/index`

### 3.2 `jumpQuery`

支持两种形式：

1. JSON 对象
2. 查询字符串

对象示例：

```json
{
  "from": "notice",
  "noticeId": "9001"
}
```

字符串示例：

```json
{
  "jumpPath": "/pages/job/list",
  "jumpQuery": "from=push&scene=recruit"
}
```

### 3.3 `actionLabel`

- 用于通知详情页按钮文案
- 为空时，前端默认显示 `去处理`

### 3.4 `sourceLabel`

- 用于通知详情页展示“来源：xxx”
- 建议简短，不要把大段业务解释塞进该字段

## 4. 后端存储口径

### 4.1 站内通知

站内通知使用：

- 表：`sys_notice`
- 字段：`remark`

要求：

- `remark` 存 JSON 字符串
- 仅承载跳转配置，不承载大段正文
- 正文说明继续放在 `notice_content`

### 4.2 APP 推送

APP 推送建议直接把同一结构放进 `payload`。

推荐 payload：

```json
{
  "jumpPath": "/pages/complaint/detail",
  "jumpQuery": {
    "complaintId": "12345",
    "from": "push"
  },
  "actionLabel": "查看处理进度",
  "sourceLabel": "投诉处理结果通知"
}
```

也兼容外层再包一层：

```json
{
  "payload": {
    "jumpPath": "/pages/complaint/detail",
    "jumpQuery": {
      "complaintId": "12345",
      "from": "push"
    },
    "actionLabel": "查看处理进度",
    "sourceLabel": "投诉处理结果通知"
  }
}
```

## 5. 前端行为口径

### 5.1 通知详情页

当接口返回：

- `jumpPath`

则页面显示操作按钮，并按以下规则跳转：

- 普通页面：`navigateTo`
- `tabBar` 页面：`switchTab`

### 5.2 推送点击

当 APP 收到：

- `type = click`

时：

1. 解析 `payload`
2. 生成统一跳转目标
3. 已登录则直接跳转
4. 未登录则暂存目标，登录成功后继续跳转

### 5.3 推送接收

当 APP 收到：

- `type = receive`

当前仅做轻提示，不直接抢跳页面。

## 6. 推荐业务样例

```json
{

  "jumpQuery": {
```

### 6.2 工资发放提醒

```json

  "jumpQuery": {
    "from": "notice"
  },
  "actionLabel": "查看工资",
  "sourceLabel": "工资发放提醒"
```

## 7. 当前约束

- `sys_notice.remark` 当前字段长度有限，建议保持简短
- 复杂扩展信息不要继续塞进 `remark`
- 如后续需要更长 payload，建议新增独立 JSON 字段或关联扩展表

## 8. 当前结论

- 后端公告、未来真实推送、客户端通知详情页，已经可以共用同一套跳转结构
- 后续若接入真实 UniPush/个推发送链，只需要把发送 payload 对齐到本约定
- 本约定优先保证“点击消息能落到正确业务页”，不扩展成第二套业务模型
