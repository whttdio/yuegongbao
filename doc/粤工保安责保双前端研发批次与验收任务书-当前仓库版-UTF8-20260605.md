# 粤工保 / 安责保双前端研发批次与验收任务书（当前仓库版）

日期：2026-06-05

## 1. 任务目标

在不拆后台、不复制主数据、不复制核心业务表的前提下，把当前仓库持续推进到以下状态：

- 两个登录入口
- 两个菜单门户
- 两个首页工作台
- 一套后台对象
- 一套共享业务逻辑
- 两套稳定的前端表达

本任务书只安排“当前仓库剩余工作”。已经完成的门户基础能力不再重复立项。

## 3. 研发批次安排

## P1：门户矩阵与角色边界验收

### 目标

把“谁默认进哪个门户、谁能看到哪些菜单、谁只能只读”做成正式验收项。

### 覆盖对象

- SQL 门户边界
  - `sql/ygb_phase9_dual_portal_scope.sql`
  - `sql/ygb_phase10_role_portal_scope.sql`
  - `sql/ygb_phase11_role_menu_portal_scope.sql`
- 前端路由与门户切换
  - `yuegongbao-ui/src/permission.js`
  - `yuegongbao-ui/src/utils/portal.js`
  - `yuegongbao-ui/src/store/modules/permission.js`

### 必测角色

- `104 ygb_enterprise_admin`
- `105 ygb_enterprise_operator`
- `106 ygb_hrss_supervisor`
- `107 ygb_emergency_supervisor`
- `108 ygb_insurer`
- `109 ygb_bank`

### 验收点

1. 默认是否进入正确门户
2. 错门户直链是否会被回跳
3. 只显示当前门户可见菜单
4. 只显示当前角色允许按钮
5. `108/109` 不出现录入、生成、治理处置类动作

## P2：共享模块继续去同质化

### 目标

把已经完成双视图外壳的模块，继续从“可区分”推进到“高频用户真的愿意长期使用”。

### 优先对象

1. `cockpit`
2. `warningRule`
3. `creditScore`
4. `statReport`
5. `aiReportConfig`
6. 仍残留共享文案痕迹的页面

### 统一升级标准

每个高频页都必须具备：

- 首屏摘要卡
- 焦点队列
- 当前选中对象摘要
- 推荐动作区
- 详情提示标签
- 只读角色收口

### 验收点

1. `ygb` 首屏看起来是办理台账，不是监管总览
2. `azb` 首屏看起来是治理台账，不是企业录入页
3. 同一对象在两个门户的摘要、标签、主动作顺序明显不同
4. 用户不依赖翻表就能找到“当前最该处理的对象”

## P3：530.1 与 6.1 正式挂接

### 目标

把业务底数与评分解释正式接起来，但不再造第二套后台。

### 后台工作

- 评分维度配置
- 评分点配置
- 权重配置
- 阈值配置
- 月度评分聚合
- 企业评分快照
- 区域评分快照
- 门户解释聚合接口

### 前端工作

`ygb` 解释以下内容：

- 劳务合规
- 扩面减损
- 工伤预防
- 整改归档

`azb` 解释以下内容：

- 安责险覆盖
- 设备安全
- 高危作业
- 风险压降
- 区域治理成效

### 验收点

1. 同一企业可在 `ygb` 与 `azb` 看到不同排序的评分解释
2. 每个得分点都能追溯到源对象或聚合指标
3. 权重调整通过配置完成，不要求前端改代码

## P4：全链路回归验收

### 目标

按“角色 + 门户 + 模块 + 动作”做一次正式回归。

### 必测模块

- `home`
- `cockpit`
- `enterprise`
- `person`
- `warning`
- `warningRule`
- `device`
- `aqInsurance`
- `heightWorkReport`
- `aiReport`
- `creditScore`
- `statReport`
- `uninsuredList`

### 回归矩阵

每个模块都至少验证以下动作：

- 列表
- 查询
- 详情
- 导出
- 新增或编辑
- 结束或处置
- 只读收口

### 验收点

1. 菜单显隐与门户范围一致
2. 按钮显隐与角色权限一致
3. 共享数据在双门户之间保持同源
4. 两个门户的页面重点与主动作不同

## 4. 开发边界规范

### 4.1 目录规范

- 共享业务逻辑
  - `src/views/<module>/useXxxPage.js`
- 粤工保前端壳层
  - `src/views/ygb/<module>/index.vue`
- 安责保前端壳层
  - `src/views/azb/<module>/index.vue`

### 4.2 共享层负责什么

- 数据查询
- 列表装载
- 摘要装载
- 详情装载
- 导出导入
- 公共字典
- 状态处理
- 只读动作判断

### 4.3 壳层负责什么

- 门户文案
- 首屏摘要
- 焦点队列
- 当前对象解读
- 动作区排序
- 角色提示

### 4.4 禁止做法

- 复制第二套后台表
- 复制第二套 API
- `azb` 直接把 `ygb` 页面改个标题就上线
- 把大量业务逻辑堆回两个壳层页面

## 5. 产品与体验验收标准

后续模块不再以“有表能查”作为完成标准，统一按工作台标准验收：

1. 首屏必须有摘要卡
2. 必须有焦点对象或焦点队列
3. 必须有当前选中对象摘要
4. 必须有推荐动作区
5. 详情必须有标签化提示或重点说明
6. 只读角色必须自动收口
7. 双门户首屏表达必须明显不同

## 6. 技术验收标准

每完成一批，必须同时满足：

1. `fnm exec --using 20.20.2 node .\node_modules\vite\bin\vite.js build --mode ygb` 通过
2. `fnm exec --using 20.20.2 node .\node_modules\vite\bin\vite.js build --mode azb` 通过
3. 共享对象仍为单源
4. 门户菜单过滤正常
5. 默认门户与错误门户回跳正常
6. 只读角色动作收口正常

## 7. 建议执行顺序

按当前仓库的真实剩余工作量，建议顺序固定为：

1. 角色菜单与门户矩阵验收
2. 共享模块继续去同质化
3. 530.1 与 6.1 评分解释挂接
4. 全链路回归

## 8. 本任务书的作用

这份任务书只做两件事：

- 给研发排批次
- 给测试定验收口径

后续如无新的产品边界变化，双前端改造应以本任务书与当前仓库实现状态为准，不再回退到“是否需要两个前端”的旧争论。
