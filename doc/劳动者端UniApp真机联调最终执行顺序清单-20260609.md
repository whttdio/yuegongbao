# 劳动者端 UniApp 真机联调最终执行顺序清单

## 1. 目的

本文只保留劳动者端 `UniApp` 当前收口阶段必须执行的真机联调步骤，不再展开页面实现说明、接口全量清单和背景分析。

适用范围：

- `App` 真机联调主链
- `H5 / mp-weixin` 构建回归后的辅助验收
- 推送、拍照、定位、离线打卡、首页与主业务链最终收口

## 2. 执行前提

执行前必须同时满足：

1. 代码基线通过
   - `npm run verify:acceptance`
   - `npm run build:h5`
   - `npm run build:app`
   - `npm run build:mp-weixin`
2. 真机与后端环境打通
   - 手机与后端地址可互通
   - 设置页“接口环境”已切到目标后端地址
   - 设置页“接口连通性检测”通过
3. 测试账号可用
   - 可正常登录劳动者端
   - 账号有首页、培训、工资、求职、投诉、通知、工会等基础数据
4. 推送链前置完成
   - `sys_config` 已配置推送网关
   - `ygb.worker.push.gateway.enabled=true`

## 2.1 多端判定口径

本清单虽然包含 `H5 / mp-weixin` 构建回归，但最终判定口径必须区分：

- `App`
  - 负责推送、系统通知权限、拍照、定位、离线打卡补传的主验收
- `H5`
  - 只负责页面与接口基础回归，不作为推送与原生权限链的最终依据
- `mp-weixin`
  - 只负责小程序兼容和构建回归，不等价于原生 `App` 推送与权限验收

执行记录里建议在每条证据旁明确写出：

- 验证端：`App / H5 / mp-weixin`
- 设备型号或运行容器
- 当前接口环境地址

## 2.2 建议的真机联调前置清单

正式进入 Step 1 前，建议再核对以下细项：

1. 设备
   - 真机可正常联网
   - 真机时间与服务端时间大致一致
   - 相机、相册、定位、通知权限未被系统强制禁用
2. 账号
   - 至少准备一个可正常登录账号
   - 最好同时准备“培训未完成”和“培训已完成”两种状态
3. 数据
   - 首页、通知、活动、视频、工资、求职、投诉、工会至少有基础数据
   - 测试环境允许写入投诉、上传归档、打卡等测试记录
4. 证据
   - 能保存页面截图
   - 能复制设置页“真机联调总览 / 全量联调导出”
   - 能拿到关键接口响应或服务端日志时间点

## 3. 执行顺序

严格按以下顺序执行，不建议跳步。

### Step 1. 清空旧快照并确认环境

操作：

- 进入 `设置`
- 点击“清空全部联调留痕”
- 在“接口环境”确认当前地址
- 点击“检测接口连通性”
- 退出并重新登录一次

必须截图/留痕：

- 设置页“接口联调快照”
- 设置页“真机联调总览”
- 设置页“执行状态面板”中“接口逐项联调清单”的状态截图

通过口径：

- 接口检测结果为 `PASS`
- 真机联调总览中接口环境正确
- “接口逐项联调清单”已从 `未开始` 进入 `进行中` 或更高状态

### Step 2. 跑推送链

操作：

- 仍在 `设置` 页确认：
  - 业务通知偏好已开启
  - 系统通知权限为已授权
  - 推送本地快照里有 `ClientId`
- 点击“重新登记推送”
- 点击“发送测试推送”
- 收到推送后点击通知
- 若未登录场景要验，则先退出登录，再从通知栏点击一次

必须截图/留痕：

- 设置页“推送本地快照”
- 设置页“最近一次测试”
- 设置页“最近推送事件”
- 设置页“执行状态面板”中“推送真机链路”的状态
- 通知栏截图
- 落页截图

通过口径：

- `ClientId` 已采集
- 推送登记成功
- 真机收到消息
- 点击后能落到目标页
- 未登录点击时，登录后能继续消费待跳转目标

### Step 3. 跑拍照上传链

操作：

- 进入 `pages/camera/index`
- 分别测试：
  - 相机拍照
  - 相册选图
- 上传图片
- 复制地址
- 使用“带入投诉举报”进入投诉页
- 回看上传记录

必须截图/留痕：

- 拍照页“联调快照”
- 上传结果区
- 上传记录区
- 设置页“执行状态面板”中“拍照上传真机链路”的状态
- 投诉页带入附件后的截图

通过口径：

- 真机权限弹窗正常
- 上传成功
- `/common/upload` 返回结构稳定
- 上传记录能回查
- 带入投诉举报的附件 URL 可用
- 设置页“真机联调总览”中的“拍照上传 / 投诉承接”摘要与页面快照不冲突

### Step 4. 跑定位与地图链

操作：

- 进入 `pages/job/map`
- 首次进入时验证定位授权
- 拒绝授权后观察降级提示
- 重新授权后点击“重新定位”
- 验证 `map-config` 和 `nearby` 返回后的地图中心、marker、列表一致性

必须截图/留痕：

- 地图页“联调快照”
- 有 marker 的地图截图
- 拒绝授权时的降级截图
- 设置页“执行状态面板”中“定位地图真机链路”的状态

通过口径：

- 定位授权弹窗正常
- 拒绝授权时能降级到默认推荐中心
- `marker` 数与岗位列表不冲突
- 地图中心、接口快照、页面说明一致
- 设置页“真机联调总览”中的“地图定位”摘要与地图页快照一致

### Step 5. 跑打卡与离线补传链

操作：

- 先确认培训状态：
  - 未完成 `10` 题时先验证锁定拦截
  - 完成培训后再继续打卡
- 在线执行一次上班打卡、一次下班打卡
- 断网后再执行一条打卡，确认进入本地队列
- 恢复网络，观察自动补传
- 再手动点一次“立即补传”

必须截图/留痕：

- 打卡页“联调快照”
- “待补传记录”
- “最近补传记录”
- 当月考勤列表
- 设置页“执行状态面板”中“离线打卡补传链路”的状态

通过口径：

- 培训未完成时，前后端都拦截
- 培训完成后可正常打卡
- 断网打卡会进入本地队列
- 恢复网络会自动补传
- 连续补传后月历列表刷新正确

### Step 6. 跑首页与五条主业务链

这一轮不要求把所有页面都深测，只保留最终收口必须确认的主链：

1. 首页
2. 培训与工资联动
3. 求职与简历联动
4. 投诉与法律咨询联动
5. 通知、活动、视频
6. 工会服务与合同

建议执行方式：

- 每跑完一条主链，就在设置页“执行状态面板”里对应更新：
  - 首页说明书口径
  - 培训与拦截联动
  - 工作台聚合验收
  - 求职简历联动验收
  - 工会合同服务验收
  - 投诉法律咨询验收
  - 通知活动视频验收
  - 社保个税验收
  - 我的资料服务验收

#### 6.1 首页

必须确认：

- 首页顺序符合说明书
- 九宫格顺序固定
- 活动、通知、视频为真实数据而不是空态
- 首页验收快照能反映真实聚合

#### 6.2 培训与工资联动

必须确认：

- 培训未完成时工资不可查看
- 培训完成后工资解锁
- 培训、答题、学习记录、课程详情四类快照与接口一致

#### 6.3 求职与简历联动

必须确认：

- 简历未完善时服务端拦截投递
- 地图、列表、详情、投递记录数据一致
- 求职链快照与真实数据一致

#### 6.4 投诉与法律咨询联动

必须确认：

- 投诉、咨询可正常提交
- 附件正常展示
- 详情页快照与真实处理数据一致
- 设置页“真机联调总览”里投诉承接摘要与投诉页、拍照页、上传归档页留痕一致

#### 6.5 通知、活动、视频

必须确认：

- 通知已读回写正常
- 活动参与与参与记录一致
- 视频进度与详情进度一致

#### 6.6 工会服务与合同

必须确认：

- 工会入口有效
- 集体合同与我的劳动合同口径清楚区分
- 验收快照与真实数据一致

## 4. 每一步必须回写的证据

每条链执行完，都至少保留以下两类证据：

1. 页面证据
   - 页面截图

2. 接口或服务端证据
   - 关键接口返回
   - 服务端日志时间点
   - 推送网关请求与响应
3. 判定端证据
   - 标明当前结论来自 `App`、`H5` 还是 `mp-weixin`
   - 若是 `App`，记录设备型号与系统版本
   - 若是 `mp-weixin`，记录开发者工具或真机环境

建议直接复用：

- 设置页“验收草稿”
- 设置页“接口联调清单”
- 设置页“联调结果记录”
  结果记录内同步回填：`验证端 / 证据来源 / 备注`
- 设置页“问题记录”
- 设置页“执行状态面板”
- 设置页“正式验收片段”

## 5. 最终通过标准

只有同时满足以下条件，才能认为劳动者端 `UniApp` 真机联调完成：

1. 推送链通过
2. 拍照上传链通过
3. 定位与地图链通过
4. 离线打卡补传链通过
5. 首页、培训、工资、求职、投诉、通知、工会主链通过
6. 设置页导出的“真机联调总览”和“验收草稿”可作为最终留痕
7. 设置页导出的“正式验收片段”可直接粘贴回正式验收文档
8. 设置页导出的“全量联调导出”可直接作为本轮联调的完整留痕文本

只要其中任意一条未通过，当前状态仍应判定为：

- `前端已实现`
- `构建已通过`
- `真机联调未完成`
