# 劳动者端 UniApp 接口环境与真机联调说明

## 1. 目的

本文用于说明劳动者端 `UniApp` 在 `H5 / App / mp-weixin` 三种构建下如何配置后端接口地址，以及真机联调前需要完成哪些环境准备。

## 2. 当前实现

当前仓库中，劳动者端 `UniApp` 的接口地址已支持三层来源：

1. 运行时存储地址
2. 构建时环境变量 `VITE_WORKER_API_BASE_URL`
3. 默认地址 `http://127.0.0.1:8080`

同时，仓库已补显式多环境构建脚本：

- `npm run build:h5:test`
- `npm run build:h5:uat`
- `npm run build:h5:prod`
- `npm run build:app:test`
- `npm run build:app:uat`
- `npm run build:app:prod`
- `npm run build:mp-weixin:test`
- `npm run build:mp-weixin:uat`
- `npm run build:mp-weixin:prod`

对应代码：

- `yuegongbao-worker-uniapp/utils/request.js`
- `yuegongbao-worker-uniapp/src/utils/request.js`
- `yuegongbao-worker-uniapp/pages/profile/settings.vue`
- `yuegongbao-worker-uniapp/src/pages/profile/settings.vue`
- `yuegongbao-worker-uniapp/.env.example`
- `yuegongbao-worker-uniapp/.env.test.example`
- `yuegongbao-worker-uniapp/.env.uat.example`
- `yuegongbao-worker-uniapp/.env.production.example`
- `doc/劳动者端UniApp全模块真机联调验收模板-20260609.md`

## 3. 优先级规则

### 3.1 运行时优先

如果在 APP“设置”页中保存了接口地址，则页面请求和上传都会优先走该地址。

运行时存储键：

- `worker_api_base_url`

适用场景：

- 真机联调切换本地局域网后端
- 测试服与预发服之间快速切换
- 不重新打包直接验证接口

### 3.2 构建时环境变量

如果没有运行时地址，则读取：

- `VITE_WORKER_API_BASE_URL`
- 当前构建模式 `MODE`

适用场景：

- CI/CD 构建不同环境包
- 固定生成测试包、预发包、生产包

当前设置页与验收导出中已可直接看到：

- 当前 `baseUrl`
- 当前地址来源
- 当前 `build mode`
- 最近检测时间与结果

### 3.3 默认地址

如果上述两者都没有，则回退：

- `http://127.0.0.1:8080`

说明：

- 该地址只适合本机联调
- 对真机通常无效
- 不应作为正式联调环境地址

## 4. 设置页使用方法

当前设置页已新增“接口环境”配置区。

### 4.1 保存接口地址

1. 打开劳动者端 `设置`
2. 找到“接口环境”
3. 输入后端地址，例如：
   - `http://192.168.1.8:8080`
   - `https://test-api.example.com`
4. 点击“保存接口地址”

保存后：

- 页面请求立即使用新地址
- 上传接口 `/common/upload` 也会同步使用新地址
- 无需重新打包
- 清理缓存时仍会保留接口地址，不会被误清空
- 打卡页会保留最近一次定位、离线补传和网络状态快照，方便真机联调时一起截图留痕
- 设置页“真机联调总览”会同步反映当前接口环境来源和最近检测结果
- 设置页“接口联调快照 / 真机联调总览 / 正式验收片段 / 全量联调导出”会同步带出当前 `build mode`

### 4.2 恢复默认

点击“恢复默认”后：

- 移除运行时地址
- 恢复为环境变量地址或默认地址

### 4.3 接口连通性检测

设置页已提供“检测接口连通性”按钮。

检测方式：

- 使用当前输入地址访问匿名接口 `/captchaImage`
- 返回 `200` 视为基础可连通

适用场景：

- 真机首次切换到局域网地址后验证是否打通
- 区分“地址错误”和“登录/业务接口错误”

补充说明：

- 接口环境联调阶段，建议同步使用设置页“执行状态面板”中的“接口逐项联调清单”
- 若需要最终回写文档，可直接使用设置页“正式验收片段”导出的阶段状态摘要
- 若需要保留一份完整联调文本，可直接复制设置页“全量联调导出”
- 若需要核对当前包到底来自 `test / uat / production` 哪个构建模式，优先看设置页“接口联调快照”中的“构建模式”字段

## 5. 真机联调建议地址

### 5.1 Android / iOS 真机联调

优先使用同一局域网下开发机地址，例如：

- `http://192.168.1.8:8080`

要求：

- 手机和开发机在同一网络
- 开发机防火墙允许访问 `8080`
- Spring Boot 服务监听地址允许局域网访问

### 5.2 H5 浏览器联调

可使用：

- `http://127.0.0.1:8080`
- `http://localhost:8080`

### 5.3 小程序联调

若 `mp-weixin` 使用测试域名，需确保：

- 微信开发者工具已配置合法 request 域名
- 或在开发者工具里临时关闭域名校验

## 6. 真机联调前置检查

## 6.1 基础网络

- 手机能访问后端地址
- 浏览器直接打开后端地址时可连通
- 若使用 HTTPS，证书需被设备接受

补充建议：

- 真机、开发机、后端服务端时间尽量保持一致，避免推送、上传、打卡时间比对时出现误判
- 若通过局域网联调，优先固定开发机 IP，避免 Wi-Fi 重连后地址变化
- 若使用 VPN、公司代理或抓包工具，先确认不会拦截 `/common/upload`、`/app/worker/**`、推送登记接口

## 6.2 后端服务

- 服务已启动
- 数据库与 Redis 正常
- 上传接口 `/common/upload` 可用
- 认证接口 `/app/worker/auth/**` 可用

补充建议：

- 准备至少一个可登录劳动者账号，并保证首页、培训、工资、求职、投诉、通知、工会等链路有基础数据
- 若要验培训拦截，请同时准备“未完成 10 题”和“已完成培训”两类账号或两类数据状态
- 若要验投诉、法律咨询、上传归档，请确认测试环境允许写入真实测试记录，并约定清理策略

## 6.3 APP 配置

- 在“设置”页确认当前生效地址正确
- 若切换了地址，建议重新登录一次
- 若做推送联调，仍需确认 `pushClientId` 已重新登记到当前环境

补充建议：

- 真机联调前先在 `设置` 页点击“清空全部联调留痕”，避免旧快照干扰判断
- 每完成一条链路后，立即复制“真机联调总览 / 执行状态面板 / 全量联调导出”中的对应片段
- 若同一台机器反复切换 `test / uat / production`，每次都重新做一次“接口连通性检测 + 重新登录”

## 6.4 证据留存要求

建议每条链路至少同步保留以下证据：

- 页面证据：
  - 页面截图
  - 页面“验收快照 / 联调快照 / 推送本地快照 / 真机联调总览”复制文本
- 接口证据：
  - 关键接口返回结构
  - 服务端时间点、日志或 traceId
- 环境证据：
  - 当前 baseUrl
  - 当前端类型（`App / H5 / mp-weixin`）
  - 当前账号与数据状态说明

## 7. 与推送联调的关系

推送联调不仅依赖推送网关，也依赖接口环境正确。

若 APP 当前保存的接口地址错误，会导致：

- `push-register` 写到错误环境
- `push-test` 调用错误环境
- 设置页读取不到正确的推送登记状态

因此，推送联调前必须先确认“接口环境”正确。

## 8. 建议的环境收口方式

当前仓库已补样例文件，建议按以下约定落正式环境文件：

### 8.1 本地开发

- `VITE_WORKER_API_BASE_URL=http://127.0.0.1:8080`

### 8.2 测试环境

- `VITE_WORKER_API_BASE_URL=https://test-api.xxx.com`
- 推荐构建命令：`npm run build:h5:test` / `npm run build:app:test` / `npm run build:mp-weixin:test`

### 8.3 预发环境

- `VITE_WORKER_API_BASE_URL=https://uat-api.xxx.com`
- 推荐构建命令：`npm run build:h5:uat` / `npm run build:app:uat` / `npm run build:mp-weixin:uat`

### 8.4 生产环境

- `VITE_WORKER_API_BASE_URL=https://api.xxx.com`
- 推荐构建命令：`npm run build:h5:prod` / `npm run build:app:prod` / `npm run build:mp-weixin:prod`

## 9. 当前限制

- 仓库已补 `.env.example`、`.env.test.example`、`.env.uat.example`、`.env.production.example`，但正式环境值仍需按部署环境落地
- 设置页已支持“检测接口连通性”，检测快照会保存在客户端本地，便于真机联调留痕；但结果尚未回传服务端
- 目前不会自动区分不同环境的 token，需要切环境后人工重新登录更稳妥

## 9.1 App / H5 / mp-weixin 差异说明

### App 端

- 支持完整推送链路：
  - `ClientId` 采集
  - 推送登记
  - 推送接收留痕
  - 通知点击落页
- 支持系统通知权限检测与“打开系统授权页”
- 真机拍照、相册、定位、离线打卡补传是本轮主验收对象
- 结论：
  - 推送、拍照、定位、离线补传是否成立，必须以 `App` 真机为准

### H5 端

- 适合做：
  - 页面结构回归
  - 接口地址切换
  - 业务页面摘要字段核对
  - 本地调试和联调文案检查
- 不适合当作完整替代：
  - 不支持完整原生推送链路
  - 不支持原生系统通知授权页能力
  - 浏览器拍照、定位权限表现受浏览器策略影响，不能替代 `App` 真机结论
- 结论：
  - `H5` 构建通过只能证明基础页面和接口逻辑可运行，不能证明推送和原生能力已验收

### mp-weixin 端

- 当前 `mp-weixin` 构建通过，可作为：
  - 路由和页面回归
  - 部分接口联调
  - 小程序端基础显示检查
- 仍需注意：
  - 需配置 request 合法域名
  - 权限申请、拍照、定位表现遵循微信小程序规则，不等于 `App`
  - 推送逻辑与原生 `App` 不等价，不能用来替代 `App` 推送验收
- 结论：
  - `mp-weixin` 构建可过，不代表推送链、原生权限链、离线补传链在 `App` 端已经成立

### 多端最终判定口径

- `App`：
  - 作为推送、拍照、定位、离线打卡补传的主判定端
- `H5`：
  - 作为页面与接口基础回归端
- `mp-weixin`：
  - 作为小程序兼容与构建回归端

因此最终验收时必须明确写出：

- 哪些结论来自 `App` 真机
- 哪些结论仅来自 `H5`
- 哪些结论仅来自 `mp-weixin`
- 不能把 `H5 / mp-weixin` 的通过直接等价为 `App` 原生链路通过

## 10. 结论

当前劳动者端 `UniApp` 已经具备：

- 运行时切换接口地址
- 上传接口跟随切换
- 构建后无需改源码即可真机联调
- 多环境显式构建脚本
- 设置页与验收导出可直接显示当前 `build mode`

剩余要做的是：

1. 按环境补 `.env` 约定
2. 用真实后端地址跑一轮登录、上传、推送、地图、打卡联调
3. 在打卡页核对“联调快照”和“最近补传记录”，确认定位降级、断网缓存、恢复补传都可追溯
4. 在设置页同步维护“执行状态面板 / 联调结果记录 / 问题记录”，其中联调结果记录至少补齐“验证端 / 证据来源 / 备注”，保证联调留痕与正式验收文档一致
5. 若需要一次性汇总留痕，优先使用设置页“全量联调导出”
