# 粤工保 / 安责保双前端研发批次与验收清单（530 与 6.1，当前仓库版）
日期：2026-06-06

## 1. 目标

在不拆后台、不复制主数据、不新增第二套核心业务表的前提下，把当前仓库推进到可持续交付状态：

- 两个登录入口稳定
- 两个门户菜单稳定
- 两个首页工作台稳定
- 一套后台对象单源
- 一套共享业务逻辑
- 两套明确不同的前端工作流表达

这份清单只安排当前仓库剩余的可执行工作，不重复已完成的门户基础改造。

## 3. 研发批次

## P1：门户与角色矩阵验收固化

### 目标

把“谁默认进哪个门户、谁看到哪些菜单、谁只能只读”做成正式验收项。

### 覆盖对象

- 门户配置
  - `src/config/portal.js`
  - `src/utils/portal.js`
- 门户守卫
  - `src/permission.js`
- 门户菜单过滤
  - `src/store/modules/permission.js`
- 角色菜单与门户 SQL
  - 已注入的门户范围 SQL

### 必测角色

- `104 ygb_enterprise_admin`
- `105 ygb_enterprise_operator`
- `106 ygb_hrss_supervisor`
- `107 ygb_emergency_supervisor`
- `108 ygb_insurer`
- `109 ygb_bank`

### 验收点

1. 默认是否进入正确门户。
2. 访问错门户直链是否自动回跳。
3. 只显示当前门户可见菜单。
4. 只显示当前角色允许动作。
5. `108/109` 不出现录入、处置、治理类操作。

## P2：首页工作台从“可区分”升级到“高频可用”

### 目标

把首页从普通统计页升级成双门户真实工作台。

### 重点页面

- `src/views/index.vue`
- `src/views/homeWorkbenchConfig.js`
- `src/views/home/`

### ygb 必须做到

- 首页先给企业办理入口，不先讲平台概念
- 财务闭环成组展示
- 监管入口保留总览与异常队列
- 重点队列能带筛选条件跳到目标页

### azb 必须做到

- 首页先看区域风险和重点对象
- 设备、预警、高处作业、安责险进入首屏
- 保险 / 银行角色只保留轻视图工作台
- 重点队列能带风险上下文跳到目标页

### 验收点

1. `ygb` 首页看起来是办理工作台，不是监管总览页。
2. `azb` 首页看起来是治理工作台，不是企业录入页。
3. 同一对象在双门户首页的摘要、标签、动作顺序明显不同。
4. 首页重点队列不是静态卡片，而是可下钻的真实入口。

## P3：共享模块去同质化

### 目标

把已做双外壳的共享模块继续往深处拆，不停留在“标题不同、表格一样”。

### 优先模块

1. `enterprise`
2. `person`
3. `warning`
4. `device`
5. `aqInsurance`
6. `heightWorkReport`
7. `creditScore`
8. `statReport`
9. `cockpit`

### 每个模块必须补齐的页面能力

- 首屏摘要卡
- 焦点对象或重点队列
- 当前选中对象摘要
- 推荐动作区
- 详情重点字段分组
- 只读角色动作收口
- 来源回跳或工作台回链

### 双门户分化要求

- `ygb` 强调办理、整改、回写、归档
- `azb` 强调风险、时效、在途、重点对象、区域治理

### 验收点

1. 详情页首屏信息块两端不再同质。
2. 列表页筛选条件能体现门户语义差异。
3. 同一条数据在两端的推荐动作排序不同。
4. 页面文案不再混用人社与应急语义。

## P4：530.1 与 6.1 的指标解释正式挂接

### 目标

把共享业务底数与双门户评分解释正式接起来。

### 后端工作

- 评分维度配置
- 得分点配置
- 权重配置
- 阈值配置
- 月度聚合任务
- 企业评分快照
- 区域评分快照
- 门户解释聚合接口

### 前端工作

`ygb` 解释以下主题：

- 劳务合规
- 扩面减损
- 工伤预防
- 整改归档

`azb` 解释以下主题：

- 安责险覆盖
- 设备安全
- 高危作业
- 风险压降
- 区域治理成效

### 验收点

1. 同一企业在 `ygb` 与 `azb` 可看到不同排序的评分解释。
2. 每个得分点都能追溯到源对象或聚合指标。
3. 调整权重不需要修改前端页面代码。
4. 评分解释能从首页、驾驶舱、报表页钻取到具体模块。

## P5：高处作业与技术防范继续产品化

### 目标

把高处作业从“已上模块”继续做成双门户都真能用的共享能力。

### 研发重点

- `ygb` 侧强调企业报备、作业完结、凭证留痕
- `azb` 侧强调高危作业在途、证书异常、区域分布、监管闭环
- 与预警中心、设备管理、AI 报告建立统一跳转关系
- 导入、凭证、结束、详情摘要在双门户保持同底数不同表达

### 验收点

1. 企业角色在 `ygb` 可顺畅完成报备闭环。
2. 监管角色在 `azb` 可快速锁定在途高危作业对象。
3. 详情、结束、凭证、告警联动路径完整。
4. 同一报备单在两个门户不存在数据分叉。

## P6：全链路回归

### 目标

按“角色 + 门户 + 模块 + 动作”做正式回归，不再只验 CRUD。

### 必测模块

- `home`
- `cockpit`
- `enterprise`
- `person`
- `warning`
- `warningRule`
- `device`
- `aqInsurance`
- `heightWorkReport`
- `aiReport`
- `creditScore`
- `statReport`
- `uninsuredList`

### 每模块最低回归动作

- 列表
- 查询
- 详情
- 导出
- 新增或编辑
- 结束或处置
- 只读收口

### 验收点

1. 菜单显隐与门户范围一致。
2. 按钮显隐与角色权限一致。
3. 共享数据在双门户之间保持同源。
4. 两个门户的页面重点与主动动作不同。

## 4. 派工规则

### 前端派工

- 共逻辑改动优先落到 `useXxxPage.js`、公共工具、API 封装
- 门户差异改动优先落到 `src/views/ygb/*` 与 `src/views/azb/*`
- 首页工作台相关统一从 `index.vue` 与 `homeWorkbenchConfig.js` 收口

### 后端派工

- 任何共享对象禁止按门户复制表
- 任何共享模块禁止再开第二套门户专用 API 主链
- 门户差异优先通过聚合接口、摘要接口、配置项解决

### 测试派工

- 不按“页面”测，要按“角色-门户-场景”测
- 每个高频角色至少覆盖一个完整工作闭环
- 对只读角色单独做动作收口回归

## 5. 页面完成标准

后续模块不再以“有表能查”作为完成标准，统一按以下标准验收：

1. 首页或列表首屏有明确摘要。
2. 有焦点对象或重点队列。
3. 有当前对象摘要区。
4. 有推荐动作区。
5. 详情有重点字段分组与标签化表达。
6. 只读角色动作自动收口。
7. 双门户首屏表达明显不同。

## 6. 技术完成标准

每一批提交前必须满足：

1. `ygb` 构建通过。
2. `azb` 构建通过。
3. 共享对象仍为单源。
4. 门户菜单过滤正常。
5. 默认门户与错门户回跳正常。
6. 只读角色动作收口正常。

## 7. 推荐执行顺序

按当前仓库的真实收益排序，建议固定为：

1. P1 门户与角色矩阵验收固化
2. P2 首页工作台高频化
3. P3 共享模块去同质化
4. P5 高处作业与技术防范产品化
5. P4 530.1 与 6.1 指标解释挂接
6. P6 全链路回归

原因很直接：

- 先把角色、门户、入口稳定住
- 再把高频用户每天都在用的首页和重点模块做实
- 最后再挂评分解释与正式回归

## 8. 本清单的作用

这份清单只做两件事：

- 给研发排批次
- 给测试定验收口径

后续如无新的产品边界变化，双前端改造统一以本清单和当前仓库真实实现为准，不再回退到“要不要双前端”的旧争论。
