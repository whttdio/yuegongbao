# 双前端拆解总览

## 1. 结论

粤工保和安责保不应继续按“同一套页面换两套登录入口”理解，而应按“一套后台能力底座 + 两个长期独立前端工作台”落地：

- `ygb`：企业办理、人社监管、工资社保合同考勤闭环
- `azb`：风险治理、设备联动、安责险协同、应急处置闭环

原因不是品牌皮肤，而是使用目标不同：

- `530.1` 文档定义的大部分主数据、业务表、状态机、接口可以共用
- `评分体系 6.1` 明确了两端统计口径、考核重点、首页优先级并不相同
- 只要首页焦点、默认动作、只读角色入口密度不同，就必须拆成双前端视图

## 2. 后台共用边界

必须继续共用：

- 企业主数据、人员主数据
- 合同、考勤、工资、社保、工伤、预警、设备、AI、安责险、信用、统计等业务表
- 状态机、权限体系、菜单树、角色菜单关系
- 门户识别底座：`X-Portal-Code + portal_scope`

不建议拆两套后台表结构的原因：

- 企业、人员、设备、预警、高处作业、工伤、AI 结果都存在强关联
- 监管部门虽然口径不同，但看的仍是同一批企业、人员、设备和事件
- 如果把后台拆成两套，数据打通和一致性成本会远高于当前双前端方案

## 3. 模块拆解原则

### 3.1 只在 `ygb` 完整呈现

- 合同备案
- 考勤上报 / 归集
- 工资监管
- 社保缴费 / 基数比对
- 个税比对
- 用工比例
- 假外包识别
- 新业态人员库

这类模块服务的是企业办理链路和人社监管链路，`azb` 最多引用结果，不应承载完整办理页面。

### 3.2 后台共用，但双前端独立视图

- 单位管理
- 人员管理
- 预警中心
- 预警规则
- 设备管理
- 安责险管理
- 工伤事件
- 事故预防资金池
- 预防项目
- 高处作业申报报备
- AI 监测报告
- AI 模型配置
- 统计报表
- 信用评价
- 漏保清单
- 驾驶舱

这类模块的表结构、接口、状态机可以共用，但 `ygb/azb` 页面必须分开，差异主要落在：

- 首页入口和摘要卡片
- 默认筛选条件
- 办理动作优先级
- 详情摘要顺序
- 只读角色与办理角色的按钮密度

### 3.3 `azb` 要长期强化的治理模块

- 驾驶舱
- 设备管理
- 预警中心
- 高处作业
- 安责险管理
- AI 监测报告
- 事故预防资金池
- 预防项目

原因是评分体系 6.1 对应急侧的考核更偏风险识别、处置时效、设备在线、安责险覆盖、技术防范闭环。

## 4. 角色归位

`ygb` 主角色：

- `104 ygb_enterprise_admin`
- `105 ygb_enterprise_operator`
- `106 ygb_hrss_supervisor`
- 企业财务、经办

`azb` 主角色：

- `107 ygb_emergency_supervisor`
- `108 ygb_insurer`
- `109 ygb_bank`
- 工地负责人
- 设备管理员

角色策略：

- 办理角色看“待我处理、异常闭环、批量动作”
- 监管角色看“区域态势、风险对象、处置时效”
- `108/109` 这类协同只读角色不再暴露复杂录入页，优先保留摘要、详情、导出、报表

## 5. 首页与体验改造方向

`ygb` 首页优先回答：

- 哪些合同待备案
- 哪些考勤未归集
- 哪些工资批次待处理
- 哪些社保 / 个税 / 漏保对象要整改
- 哪些高处作业正在进行

`azb` 首页优先回答：

- 哪些红黄预警待处置
- 哪些设备离线 / 异常 / 待授权
- 哪些高危作业未闭环
- 哪些保单、资金池、AI 风险对象最需要处理

页面结构统一建议：

1. 顶部：模块定位 + 当前门户说明
2. 中部：摘要卡片 + 当前焦点对象 + 下一步动作提示
3. 底部：筛选、操作栏、表格、详情抽屉

原则上不再用“分页列表 rows 临时统计摘要”的方式拼工作台。

## 6. 当前技术底座结论

当前仓库已具备继续推进双前端的关键底座：

- 登录请求头已按门户附带 `X-Portal-Code`
- 菜单与按钮已支持 `portal_scope`
- 角色已支持 `allowed_portal_scope / default_portal_code`
- 角色菜单授权已支持 `sys_role_menu.portal_scope`
- 登录、路由、权限串、角色授权页已打通门户感知链路

这意味着后续重点不再是“能不能分开”，而是“哪些共享模块应该升级成双视图工作台”。

## 7. 实施优先级

`P0`：

- 首页摘要改为真实 `summary/dashboard`
- 继续复核 `portal_scope + 角色矩阵`
- 把共享高频模块从基础 CRUD 升级为门户差异化工作台

`P1`：

- 持续强化 `AI 报告 / 统计报表 / 驾驶舱`
- 扩大只读角色轻视图覆盖面
- 收口跨门户误露出的按钮和入口

`P2`：

- 按角色进一步拆默认工作台
- 为企业财务、工地负责人、设备管理员做更轻量的专属入口
