# 粤工保安责保双前端研发批次与验收清单（现状校正版）

日期：2026-06-06

## 1. 目标

在保持“一套后台”的前提下，把当前系统稳定落成“两前端门户”：

- `ygb`：企业办理、人社监管、财务对账主链
- `azb`：应急监管、安责险协同、设备安全、风险治理主链

交付不是做第二套后台，而是：

- 补齐共享模块的双壳体验
- 收口各角色默认入口
- 固化页面高频使用顺序
- 统一 530.1 与 6.1 的解释和验收口径

## 2. 当前已具备基础

当前仓库已具备以下基础，可直接继续开发，不需要回炉重做：

- 双登录入口：`/login/ygb`、`/login/azb`
- 门户品牌配置：`src/config/portal.js`
- 门户路由守卫与角色跳转：`src/utils/portal.js`
- 菜单按门户过滤：`src/store/modules/permission.js`
- 双工作台蓝图：`src/views/homeWorkbenchConfig.js`
- 双目录结构：`src/views/ygb`、`src/views/azb`
- 共享页面逻辑层：`src/views/<module>/useXxxPage.js`

因此本期工作重点不是“要不要双前端”，而是“哪些模块继续双壳深化，哪些模块只留在 ygb，哪些模块在 azb 强化风险表达”。

## 3. 研发批次

### 批次 0：门户底座固化

目标：把双门户基础彻底固定，避免后续模块改造反复改底层。

开发项：

- 固化 `portalCode` 解析、记忆和登录重定向
- 固化菜单按门户过滤逻辑
- 固化 `ygb`、`azb` 两套首页工作台
- 固化企业角色和监管角色默认门户跳转

验收项：

- 访问 `/login/ygb` 与 `/login/azb`，品牌和引导文案不同
- 同一账号登录后，按角色进入默认门户
- 不属于当前门户的菜单不展示
- 不需要复制第二套路由和第二套接口即可切换门户

### 批次 1：共享模块统一收口为“共享逻辑 + 双壳”

目标：把共享模块彻底纳入统一模式，避免一部分页面继续串用单壳。

范围：

- `enterprise`
- `person`
- `warning`
- `warningRule`
- `device`
- `aqInsurance`
- `preventionFund`
- `preventionProject`
- `injuryEvent`
- `heightWorkReport`
- `aiReport`
- `aiReportConfig`
- `creditScore`
- `statReport`
- `uninsuredList`
- `cockpit`

开发要求：

- 共享查询、表格、校验、导出、状态逻辑放进 `useXxxPage.js`
- `ygb` 和 `azb` 只负责页面语义、卡片编排、摘要文案、入口顺序
- 同一对象支持从工作台/驾驶舱/预警中心带筛选条件跳转
- 重置查询时保留工作台上下文，不丢失来源筛选

验收项：

- 共享模块在 `ygb`、`azb` 都可访问
- 两端看到的是同一批业务数据，不产生双份记录
- 两端首页入口不同、详情摘要不同、推荐动作不同
- 从工作台跳转到模块页后，上下文筛选可保留并可清除

### 批次 2：`ygb` 办理主链定型

目标：让企业管理员、工地负责人、操作员、财务长期高频使用顺手。

范围：

- `contract`
- `attendanceRaw`
- `attendanceMonthly`
- `salaryBatch`
- `salaryDetail`
- `socialPayment`
- `socialBaseCompare`
- `taxCompare`
- `employmentRatio`
- `fakeOutsourcing`
- `newformWorker`
- `occupationMonitor`

开发要求：

- 首页按“办理 > 对账 > 整改 > 归档”排序
- 高频入口前置，不让企业用户先读汇报型页面
- 财务相关模块成组展示，减少跨页跳转
- 预警中心与扩面减损要回挂到合同、考勤、工资、社保整改链

验收项：

- 企业管理员能从首页直达合同、考勤、工资、高处作业
- 财务能从首页直达工资批次、工资明细、社保缴费、税务比对
- `azb` 不再承接这些模块的完整录入办理页
- `azb` 若引用这些数据，只显示摘要、风险结论、评分解释

### 批次 3：`azb` 风险治理主链定型

目标：让应急监管员、保险公司、银行、现场治理角色看的是风险与处置，不是企业办理流水。

范围：

- `cockpit`
- `warning`
- `device`
- `aqInsurance`
- `heightWorkReport`
- `aiReport`
- `creditScore`
- `preventionFund`
- `preventionProject`
- `injuryEvent`

开发要求：

- 首页按“风险 > 处置 > 时效 > 区域治理”排序
- 设备、安责险、高处作业、AI 报告首屏优先
- 保险和银行保持只读协同，不暴露复杂录入流
- 企业角色进入 `azb` 后切换成现场治理视角

验收项：

- 应急监管员默认进入 `azb`
- 保险公司只看到安责险、信用评价、统计报表、资金协同等只读视图
- 银行只看到工资风险摘要、信用评价、统计报表类只读视图
- 企业角色进入 `azb` 时，先看到设备、预警、高处作业，而不是合同工资

### 批次 4：评分与报告解释统一

目标：同一底数，双端不同解释，不把评分规则写死在前端页面。

开发要求：

- 530.1 对应 `ygb` 解释链
- 6.1 对应 `azb` 解释链
- 权重、阈值、得分点配置化
- AI 报告、统计报表、驾驶舱从同一底数输出双口径摘要

验收项：

- 同一企业在两端看到的核心底数一致
- `ygb` 偏办理成效与整改闭环解释
- `azb` 偏风险等级、治理成效、区域热区解释
- 不新增第二套评分表和第二套页面硬编码规则

## 4. 派工方式

建议按四类任务并行派工：

### 前端壳层

- 负责人：前端
- 任务：登录页、首页工作台、卡片编排、模块摘要、详情高亮、门户跳转

### 共享页面逻辑

- 负责人：前端
- 任务：`useXxxPage.js`、通用筛选、查询重置、上下文跳转、导出导入行为统一

### 后端与权限

- 负责人：后端
- 任务：统一接口、角色菜单口径、门户菜单范围、评分解释接口、只读角色权限控制

### 测试与验收

- 负责人：测试/产品
- 任务：双门户登录、角色跳转、共享数据一致性、门户差异性、工作台闭环

## 5. 验收总清单

### 门户层验收

- `ygb`、`azb` 登录页样式和文案不同
- 首页工作台分工不同
- 菜单树按门户正确收口
- 默认门户随角色变化

### 数据层验收

- 企业、人员、预警、设备、高处作业、AI、安责险、工伤等数据只保留一套底数
- 两端查询结果一致，不生成门户专属重复数据
- 导入导出、详情、状态变化仍走统一接口

### 页面层验收

- `ygb` 页面组织顺序贴合企业办理和财务对账
- `azb` 页面组织顺序贴合风险治理和监管处置
- 共享模块两端均可访问，但文案、摘要、入口排序不同
- 工作台跳转保留上下文筛选

### 角色层验收

- 企业管理员、企业经办员默认进 `ygb`
- 人社监管员默认进 `ygb`
- 应急监管员、保险公司、银行默认进 `azb`
- 保险和银行维持只读，不暴露复杂录入动作

## 6. 本期禁止事项

本期研发明确禁止：

1. 为 `azb` 新建第二套企业/人员/预警/设备/工伤/AI/评分业务表
2. 为 `azb` 复制第二套后台控制器和服务层
3. 在前端页面硬编码评分权重、评分阈值、门户专属底数
4. 把企业办理型模块再完整复制到 `azb`
5. 把双前端回退成“同一套页面只换标题”
