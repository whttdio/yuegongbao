## 3. 固定实施原则

### 3.1 后端原则

- 统一主数据
- 统一状态机
- 统一权限校验
- 统一 CRUD
- 优先补聚合接口，不复制业务表

固定要求：

- 不新建“粤工保后台”和“安责保后台”两套服务。
- 共享模块只补门户聚合能力，不复制底层业务对象。

### 3.2 前端原则

- `ygb` 不是默认后台壳，必须是办理工作台。
- `azb` 不是换皮频道，必须是治理工作台。
- 共享模块必须拆成双语义页面。
- 高频页面必须有：
  - 摘要
  - 焦点队列
  - 当前对象
  - 推荐动作
  - 详情联动

### 3.3 测试原则

- 不按单页 CRUD 验收。
- 按 `角色 + 门户 + 模块 + 动作` 四维验收。

## 5. 开发批次

## 5.1 P0：收口共享模块改造底座

### 目标

把已确认需要双视图的共享模块，统一收敛到“共享组合逻辑 + 门户壳层”的实现模式。

### 页面范围

优先级从高到低：

1. `views/ygb/device` + `views/azb/device`
2. `views/ygb/cockpit` + `views/azb/cockpit`
3. `views/ygb/statReport` + `views/azb/statReport`
4. `views/ygb/creditScore` + `views/azb/creditScore`
5. `views/ygb/warningRule` + `views/azb/warningRule`

### 前端动作

每个共享模块统一补齐：

1. `src/views/<module>/use<Module>Page.js`
2. `ygb` 页面壳
3. `azb` 页面壳
4. 角色轻视图控制
5. 摘要卡、焦点队列、详情联动

### 后端动作

为共享模块统一补齐或校准聚合接口：

- `summary`
- `dashboard`
- `detail-hint`
- `focus-queue`

### 验收标准

1. 共享逻辑不再散落在两个门户页面里重复维护。
2. `vite build --mode ygb` 通过。
3. `vite build --mode azb` 通过。
4. 只读角色看不到新增、治理、模拟、生成类按钮。

## 5.2 P1：补齐 `ygb` 高频办理工作台

### 目标

把仍停留在基础 CRUD 感的 `ygb` 高频页面，升级成企业管理员、工地负责人、操作员、财务可长期高频使用的工作台。

### 页面范围

优先级从高到低：

1. `views/ygb/contract`
2. `views/ygb/attendanceRaw`
3. `views/ygb/attendanceMonthly`
4. `views/ygb/salaryBatch`
5. `views/ygb/socialPayment`
6. `views/ygb/socialBaseCompare`
7. `views/ygb/taxCompare`
8. `views/ygb/uninsuredList`

### 前端动作

每页统一补齐：

1. 摘要卡
2. 办理焦点队列
3. 当前选中对象摘要
4. 推荐办理动作区
5. 默认筛选条件
6. 表头业务说明
7. 详情提示标签

### 后端动作

为上述模块补齐：

- 区域监管默认筛选条件
- 办理状态统计字段
- 详情摘要字段

### 验收标准

1. 企业管理员进入页面 3 秒内能看到待办焦点。
2. 当前对象与详情抽屉联动正常。

4. 页面不再只停留在“搜一搜、点新增、点导出”的基础形态。

## 10. 最终执行结论

1. 这个项目不是“一套后台两个登录页”，而是“一套后台、两个长期业务门户”。
2. 共享模块必须坚持“后台统一、前端双语义”，不能再回退成通用 CRUD 页面。
3. 短期优先级是先收口共享模块模式，再补齐 `ygb` 高频办理页和 `azb` 治理页，最后接评分体系。
4. 后续排期、派工、联调、验收统一按本任务书推进，不再以“基础增删改查已经有了”作为完成标准。
