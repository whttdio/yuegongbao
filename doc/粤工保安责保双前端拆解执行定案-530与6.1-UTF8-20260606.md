# 粤工保安责保双前端拆解执行定案（530.1 / 6.1 / 当前仓库版）

日期：2026-06-06

## 1. 定案结论

当前系统长期结构固定为：

- 一套后台
- 两个前端门户：`ygb`、`azb`
- 两套登录页、首页工作台、路由壳和菜单显隐
- 一套企业、人员、预警、设备、高处作业、工伤、安责险、AI、统计等业务底座

这不是“同一个后台换两个标题”，而是：

- `ygb` 承接 `530.1` 的主业务链，偏企业办理、财务对账、人社监管、整改闭环
- `azb` 承接 `6.1` 的监管解释链，偏应急监管、安责险协同、设备安全、风险治理
- 两端共用同一批业务对象和接口，但页面组织、首页入口、详情摘要、推荐动作必须分开

## 4. 模块拆解定案

### 4.1 只在 `ygb` 完整承载的办理链模块

这些模块属于企业办理、财务对账、人社合规主链，不建议在 `azb` 再做完整办理页：

- `contract`
- `attendanceRaw`
- `attendanceMonthly`
- `salaryBatch`
- `salaryDetail`
- `socialPayment`
- `socialBaseCompare`
- `taxCompare`
- `employmentRatio`
- `fakeOutsourcing`
- `newformWorker`
- `occupationMonitor`

执行规则：

- `azb` 如需使用，只允许消费摘要、风险结论、评分解释
- `azb` 不再承接这些模块的原始录入与办理流程

### 4.2 共后台 + 双前端外壳的共享模块

以下模块必须坚持“共享逻辑 + 双壳表达”：

- `aiReport`
- `aiReportConfig`
- `aqInsurance`
- `cockpit`
- `creditScore`
- `device`
- `enterprise`
- `heightWorkReport`
- `injuryEvent`
- `person`
- `preventionFund`
- `preventionProject`
- `statReport`
- `uninsuredList`
- `warning`
- `warningRule`

执行规则：

- 共享逻辑层放在 `src/views/<module>/useXxxPage.js`
- `ygb` 壳层放在 `src/views/ygb/<module>/index.vue`
- `azb` 壳层放在 `src/views/azb/<module>/index.vue`
- 同一对象在两端都可查询，但首页入口、摘要顺序、详情重点、推荐动作不能相同

### 4.3 `azb` 主责强化模块

以下模块虽然共后台，但在 `azb` 必须明显强化监管语义：

- `aqInsurance`
- `device`
- `warning`
- `heightWorkReport`
- `aiReport`
- `creditScore`
- `statReport`
- `preventionFund`
- `preventionProject`
- `injuryEvent`

`azb` 页面应优先强调：

- 当前风险等级
- 区域热区
- 在途处置
- 超时未闭环
- 重点对象队列
- 下一步治理动作

### 4.4 `ygb` 主责强化模块

`ygb` 必须保持第一优先级的业务链：

- 合同备案
- 考勤采集与归集
- 工资批次与工资明细
- 社保缴费与基数比对
- 税务比对
- 预警整改
- 扩面减损
- 高处作业企业报备闭环

`ygb` 页面应优先强调：

- 当前待办
- 办理堵点
- 回写状态
- 月度归档节点
- 企业高频入口
- 财务高频入口

- `108/109` 保持只读视图，不暴露完整录入、整改、治理动作

## 6. 530.1 与 6.1 的挂接方式

### 6.1 `530.1` 对应 `ygb`

`530.1` 的主价值链应落到 `ygb`：

- 劳务合规
- 工资发放
- 社保税务比对
- 用工比例与假外包治理
- 工伤预防
- 扩面减损

### 6.2 `6.1` 对应 `azb`

`6.1` 的主解释链应落到 `azb`：

- 安责险覆盖
- 设备安全
- 技术防范
- AI 风险识别
- 隐患整改
- 区域治理成效

### 6.3 固定挂接原则

- 同一企业在 `ygb` 和 `azb` 共用同一底数
- 两端只改变解释顺序、摘要视角、推荐动作
- 评分权重、阈值、得分点必须配置化，不能写死在页面
- 首页、驾驶舱、报表允许按门户输出不同解释口径

## 7. 当前仓库继续实施的开发批次

- 完成所有共享模块的工作台上下文透传

- 固化 `enterprise/person/warning/device/heightWorkReport/aiReport/preventionProject/uninsuredList` 的双壳结构
- `ygb` 强化办理闭环
- `azb` 强化风险队列与治理动作

## 9. 研发执行要求

后续所有双前端改造统一按以下口径执行：

- 后台坚持单套对象、单套状态机、单套核心接口
- 门户差异优先落在前端壳层，不回灌成后端双分支
- 共性模块一律走“共享逻辑 + 双外壳”
- 企业办理主链收口到 `ygb`
- 风险治理主链强化到 `azb`
- 同一对象允许双视图，不允许双建模
