# 双前端研发派工与验收执行单

## 1. 用途

这份执行单直接给产品、前端、后端、测试排期使用，只回答四件事：

1. 现在先改什么
2. 后端先补什么
3. 前端每批怎么落
4. 每批怎么验收

把 `ygb` 首页真正变成高频办理入口，不再让企业管理员、操作员、财务、人社监管看到近似同构的首页。

| 页面 | 派工内容 |
| --- | --- |
| `views/index.vue` | 核对与 `ygb/cockpit` 的职责边界，避免首页与驾驶舱重复承载角色逻辑 |
| `ygb/cockpit/index.vue` | 继续按角色拆摘要卡顺序、焦点队列顺序、默认焦点对象、模块组顺序 |
| `ygb/statReport/index.vue` | 首页入口与月报路径保持一致，承接办理闭环月报 |
| `ygb/heightWorkReport/index.vue` | 保持企业办理语义，强调报备、补证、结束留痕 |

### 4.3 后端派工

| 能力 | 派工内容 |
| --- | --- |
| 首页聚合 | 继续补 `ygb` 企业办理链、财务链、监管链的摘要和重点对象队列 |
| 角色队列 | 允许首页按 `104/105/106` 返回不同推荐顺序 |
| 详情联动 | 当前对象摘要字段与台账详情保持一致，避免首页点进去后语义断层 |

### 4.4 P0 验收

1. `104` 登录后优先看到合同、考勤、工资、社保、预警、高处作业闭环
2. `105` 登录后优先看到录入、修正、结束登记，不先看到监管汇总
3. 财务进入首页先看到工资、社保、个税、对账异常
4. `106` 进入首页先看到区域异常对象、整改闭环、归档月报
5. `vite build --mode ygb` 通过

把 `530.1` 的业务底数正式转换成 `6.1` 的评分口径，让双前端不仅页面不同，连解释逻辑也不同。

### 6.3 前端派工

## 7. P3：SQL、角色、菜单与按钮收口

### 7.1 目标

把代码、SQL、测试口径统一，避免出现：

- 页面能看到但后端没权
- 角色已注入但门户归属错误
- 共享模块在错误门户暴露

### 7.2 SQL 派工

固定围绕以下字段和脚本核对：

- `sys_menu.portal_scope`
- `sys_role.allowed_portal_scope`
- `sys_role.default_portal_code`
- `sys_role_menu.portal_scope`
- `sql/ygb_phase8_height_work_role.sql`
- `sql/ygb_phase9_dual_portal_scope.sql`
- `sql/ygb_phase10_role_portal_scope.sql`
- `sql/ygb_phase11_role_menu_portal_scope.sql`

### 7.3 角色矩阵核对

1. `ygb` 独占模块不得出现在 `azb` 主菜单
2. `azb` 治理专属模块不得污染 `ygb` 办理主链
3. `108/109` 统一只读
4. 高处作业、工伤、预警、设备、AI、安责险等共享模块按双视图授权

### 7.4 P3 验收

1. 菜单显隐与角色矩阵一致
2. 按钮显隐与后端权限一致
3. 同一角色跨门户进入时会自动归位到允许门户
4. SQL 重复执行不产生重复菜单、角色、关系数据

## 8. 每个共享模块的标准派工模板

任何共享模块，都按下面 8 项派工：

1. 模块归属：`ygb` 独占 / 双视图 / `azb` 主责
2. 共后台对象：主表、明细表、状态机是否复用
3. `ygb` 页面语义：办理、归档、整改还是监管
4. `azb` 页面语义：治理、协同、风险还是时效
5. 聚合接口：是否补 `summary/dashboard`
6. 详情重点：双门户详情字段是否不同
7. 轻视图：`108/109` 是否要收口
8. 验收命令：至少包含 `vite build --mode ygb` 或 `vite build --mode azb`
