# 粤工保安责保双前端研发批次与验收任务书（可执行版）

日期：2026-06-05

## 1. 任务书目标

这份任务书不再讨论方向，只回答四个问题：

1. 先做什么。
2. 前端改什么。
3. 后端补什么。
4. 验收按什么标准过。

## 2. 当前代码基线

当前仓库已经具备继续推进双前端的基础：

- 双登录入口已存在：
  - `/login/ygb`

- 双目录已形成：
  - `yuegongbao-ui/src/views/ygb`

  - `yuegongbao-ui/src/utils/roleView.js`
- 门户权限底座已接入：
  - `sql/ygb_phase9_dual_portal_scope.sql`

- 现在最缺的不是门户底座。
- 现在最缺的是模块语义补齐、工作台化升级、评分解释接入和验收口径统一。

## 3. 固定实施原则

### 3.1 后端原则

- 统一主数据
- 统一状态机
- 统一权限校验
- 统一 CRUD
- 优先补聚合接口，不复制业务表

固定要求：

- 不新建“粤工保后台”和“安责保后台”两套服务。
- 共享模块只补门户聚合能力，不复制底层业务对象。

### 3.2 前端原则

- `ygb` 不是默认后台壳，必须是办理工作台。
- `azb` 不是换皮频道，必须是治理工作台。
- 共享模块必须拆成双语义页面。
- 高频页面必须有：
  - 摘要
  - 焦点队列
  - 当前对象
  - 推荐动作
  - 详情联动

### 3.3 测试原则

- 不按单页 CRUD 验收。
- 按 `角色 + 门户 + 模块 + 动作` 四维验收。

## 4. 开发批次

## 4.1 P0：补齐 `ygb` 剩余主链工作台

### 目标

把仍停留在基础 CRUD 感的 `ygb` 高频页面，全部升级成企业管理员、工地负责人、操作员、财务能长期使用的工作台。

### 页面范围

优先级从高到低：

1. `views/ygb/device`
2. `views/ygb/enterprise`
3. `views/ygb/person`
4. `views/ygb/aqInsurance`
5. `views/ygb/statReport`
6. `views/ygb/preventionProject`
7. `views/ygb/aiReportConfig`
8. `views/ygb/creditScore`

说明：

- `salaryBatch`
- `salaryDetail`
- `contract`
- `attendanceMonthly`
- `taxCompare`
- `employmentRatio`
- `fakeOutsourcing`
- `newformWorker`
- `occupationMonitor`
- `socialPayment`
- `socialBaseCompare`
- `heightWorkReport`

这些页面已经基本进入工作台模式，本批次以剩余页面补齐一致性为主。

### 前端动作

每页统一补齐：

1. 摘要卡
2. 焦点队列
3. 当前选中对象摘要
4. 推荐动作区
5. 焦点优先可见列表
6. 表头说明
7. 详情提示标签
8. 只读角色限制

### 后端动作

为上述模块补齐门户聚合接口：

- `summary`
- `focus-queue`
- `detail-hint`
- `dashboard`

同时补充：

- 企业角色和监管角色的默认筛选条件
- 焦点队列统计字段
- 详情摘要字段

### 验收标准

1. 企业管理员进入页面 3 秒内能看到待办焦点。
2. 当前选中对象与详情抽屉联动正常。
3. 只读角色看不到新增、治理、模拟、生成类按钮。
4. `vite build --mode ygb` 通过。

## 4.2 P1：补齐 `azb` 剩余治理工作台

### 目标

继续压缩 `azb` 中的通用 CRUD 感，强化应急治理、安责险协同和风险处置语义。

### 页面范围

1. `views/azb/preventionFund`
2. `views/azb/preventionProject`
3. `views/azb/aiReportConfig`
4. `views/azb/cockpit`
5. `views/azb/heightWorkReport`
6. `views/azb/enterprise`
7. `views/azb/person`

### 前端动作

每页统一补齐：

1. 风险摘要卡
2. 风险队列
3. 当前风险对象
4. 推荐处置动作
5. 详情时效提示
6. 只读轻视图入口

### 后端动作

补 `azb` 口径聚合字段：

- 重大隐患数
- 重复预警数
- 超时未处置数
- 离线设备数
- 锁机失败数
- 在途高危作业数
- 保单风险摘要

### 验收标准

1. `107` 看得到治理入口和处置动作。
2. `108/109` 看得到摘要、详情、报表，但看不到治理动作。
3. 同一对象在 `azb` 详情里，风险等级、剩余时效、处置建议优先展示。
4. `vite build --mode azb` 通过。

`azb` 首页突出：

- 驾驶舱

- 设备

- 安责险

角色默认入口固定：

- `104/105/106` 默认进 `ygb`

3. `azb` 首屏不出现企业劳务办理主语义。

必须验证：

- 录入、导入、修改、结束登记可用
- 导出、监管处置、复杂治理动作受限

### 6.3 `106 ygb_hrss_supervisor`

必须验证：

- 区域视角可见
- 整改闭环和统计入口优先
- 不暴露企业录入主链

### 6.4 `107 ygb_emergency_supervisor`

必须验证：

- 红警、设备、高危作业、AI 风险优先
- 处置、督办、追踪动作可用

必须验证：

- 只读摘要和详情可用

必须验证：

- 只读工资风险摘要、信用评价、报表可见

## 8. 最终执行结论

1. 这个项目不是“一套后台两个登录页”，而是“一套后台、两个长期业务门户”。
2. 共享模块必须坚持“后台统一、前端双语义”，不能再回退成通用 CRUD 页面。
3. 短期开发优先级应先收口 `ygb` 高频工作台，再补齐 `azb` 治理工作台，最后接评分体系。
4. 后续排期、派工、联调、验收统一按本任务书推进，不再以“基础增删改查已经有了”作为完成标准。
