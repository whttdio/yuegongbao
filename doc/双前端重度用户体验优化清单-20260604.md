# 双前端重度用户体验优化清单

## 1. 目标

本清单不讨论“能不能用”，只讨论“企业管理员、工地负责人、操作员、财务、监管员能不能长期高频使用”。

判断标准只有三条：

1. 是否减少重复点击
2. 是否减少来回切页
3. 是否把真正高频的信息提前暴露

## 2. 当前主要问题

### 2.1 共性模块仍残留基础 CRUD 体验

- 进入页面先看到表格，而不是先看到风险/待办/重点对象
- 卡片摘要依赖当前页分页数据，口径不稳定
- 当前选中对象、治理焦点、详情说明不足

### 2.2 双门户虽然分开了入口，但没有完全分开工作台

- 很多模块还是“同一页换文案”
- 首页默认入口差异不够明显
- 用户进入后还需要自己判断该先做什么

### 2.3 角色视角没有充分前置

- 企业管理员关心的是批处理和异常闭环
- 工地负责人关心的是现场状态和作业风险
- 财务关心的是金额、批次、回单、失败原因
- 监管关心的是区域态势、风险对象、整改时效

这些信息在现有页面里都还不够靠前。

## 3. 可直接执行的优化动作

### 3.1 页面结构统一改成“三段式”

适用于双门户高频页：

1. 顶部：模块定位 + 当前重点提示
2. 中部：摘要卡片 + 当前焦点 + 当前选中对象
3. 下部：搜索、操作栏、表格、详情抽屉

### 3.2 摘要全部改成后端聚合

优先规则：

- 任何摘要卡片都不再从当前页 `rows` 临时计算
- 统一补 `summary` 或 `dashboard` 接口
- 分页列表只负责台账明细，不负责门户口径

### 3.3 详情抽屉必须补“下一步动作提示”

不是只显示字段，还要告诉用户：

- 当前对象有什么风险
- 下一步应该做什么
- 影响哪些关联模块

### 3.4 企业侧页面强化批处理

`ygb` 侧后续优先补：

- 待我处理
- 本月异常
- 批量导入/导出
- 财务失败原因聚合
- 跨模块整改入口

### 3.5 安责保页面强化风险治理

`azb` 侧后续优先补：

- 区域态势
- 高危对象清单
- 预警闭环时效
- 当前活跃规则/模型/保单版本
- 高危作业和设备状态联动

## 4. 模块级优先级

### P0 已应完成

- 驾驶舱
- 预警中心
- 设备管理
- 安责险管理
- 高处作业
- AI 报告

### P1 本轮继续补齐

- 企业管理摘要改后端聚合
- AI 模型配置摘要改后端聚合
- 双门户方案文档按“共性底座/差异页面”重写

### P2 下一轮建议

- 双门户首页按角色拆默认入口
- 粤工保财务视角工作台
- 安责保工地负责人轻量工作台
- 只读角色专属摘要页

## 5. 验收方式

### 5.1 企业管理员

- 进入 `ygb` 后 10 秒内能看到待处理事项
- 不进表格也能知道本月异常量

### 5.2 财务

- 进入工资相关页面后，先看到批次状态、失败数、待回单数
- 不需要翻到明细页才知道问题在哪

### 5.3 工地负责人

- 进入 `azb` 后，先看到高危作业、设备、预警和现场风险
- 当前企业或项目的风险对象能快速定位

### 5.4 监管员

- 首页先看到区域态势和重点对象
- 不再靠多个列表页自己拼全局判断

## 6. 当前仓库对应关系

本轮已经形成的正确方向是：

- 门户底座：`portal_scope + X-Portal-Code`
- 双端页面目录：`views/ygb` 与 `views/azb`
- 高频治理页：逐步改成 `summary/dashboard + 列表明细` 双轨结构

后续只要继续按这个结构推进，系统就会从“基础 CRUD 平台”逐步变成“可长期重度使用的双门户业务工作台”。
