# 双前端改造执行清单

## 1. 目标

把当前“一个后台、两个能登录的前端”升级成“一个后台、两个可长期高频使用的业务工作台”。

执行基线：

- 不拆库
- 不复制核心业务表
- 不复制核心 CRUD 控制器
- 允许新增门户汇总接口
- 允许同一业务模块在 `ygb/azb` 分别维护独立页面

## 3. 待执行批次

### 第一批：补齐剩余安责保高频页

目标：把安责保从“部分独立”补成“核心工作闭环独立”。

实施结果：

- `person`
- `enterprise`
- `uninsuredList`
- `warningRule`

执行要求：

- 不再 import `@/views/ygb/*`
- 改成 `azb` 独立页面
- 继续复用共享 API
- 页面结构按应急侧重排，而不是照搬 `ygb`

验收结果：

- 搜索 `import .*@/views/ygb/` 时，上述四页已不再命中
- 四页均已补齐安责保自己的汇总卡片、风险摘要、当前选中对象总览和说明文案

### 第二批：补齐门户级汇总接口

目标：避免 `azb` 首页和治理页继续靠分页列表拼装数据。

本轮已补齐：

- 安责保驾驶舱汇总接口
- 安责保险种覆盖汇总接口
- 设备态势汇总接口
- 高处作业态势汇总接口
- 漏保整改闭环汇总接口
- `person / enterprise / warningRule / aiReportConfig` 门户摘要接口

下一步优先新增：

- 首页快捷入口聚合接口
- AI 报告首页摘要接口
- 统计报表门户推荐接口

接口设计原则：

- 控制器可独立
- 查询内核尽量共用 service
- 只做汇总，不复制明细业务表

验收标准：

- 首页和治理页关键卡片不再依赖列表首屏数据拼装
- 接口响应里明确带门户语义字段，不再混入粤工保标题文案

### 第三批：校正角色矩阵与菜单边界

目标：确保“看到什么页面”和“能点什么按钮”真正符合双门户分工。

执行内容：

- 复核 `portal_scope`
- 复核角色菜单分配
- 复核按钮级权限边界
- 复核同一角色跨门户登录后的菜单收敛

重点检查：

- `ygb` 独占模块按钮必须 `portal_scope=ygb`
- `azb` 高危治理相关菜单必须对 `107/108/109` 准确开放
- 企业角色在 `azb` 不应看到人社办理型菜单
- 保险、银行角色默认只读

验收标准：

- 同一账号登录 `ygb` 与 `azb`，菜单树不同
- 同一接口在两个门户返回的按钮权限不同
- 角色授权页切门户保存后，不会覆盖另一个门户的菜单关系

### 第四批：重做双门户首页工作台

目标：把两个前端真正做成两套长期使用入口。

`ygb` 首页必须强化：

- 待办合同
- 待归集考勤
- 待发工资批次
- 社保/个税异常
- 漏保整改
- 高处作业报备

`azb` 首页必须强化：

- 设备离线/锁机
- AI高风险事件
- 高处作业进行中
- 安责险到期风险
- 整改超时
- 区域态势

验收标准：

- 两个首页入口结构明显不同
- 用户 3 次点击内能到高频业务
- 不再依赖顶部 Banner 才知道自己在哪个门户

## 4. 模块改造优先级

### P0

- 安责保首页快捷入口
- AI 报告/统计报表的门户口径说明统一化
- 双门户首页默认入口拆分

原因：

- 包装页已清理完成
- 下一阶段瓶颈转为门户级汇总接口与首页入口组织

### P1

- 共享页中的门户感知文案清理
- 更多只读角色的视图瘦身
- 官网入口与后台快捷跳转打通

## 5. 多角色体验改造要求

### 企业管理员

- `ygb` 重点是办理闭环
- `azb` 重点是现场风险和整改闭环
- 同一个企业管理员进入两个门户后，默认首页不能相同

### 工地负责人

- 优先看到当日作业、现场风险、高处作业、预警处置
- 页面应减少财务和历史配置噪音

### 操作员

- 优先看到待录入、待完成、待整改
- 表单页要支持连续录入和快速返回列表

### 财务经办

- 只在 `ygb` 强化工资、社保、个税、漏保闭环
- 在 `azb` 不应承担主要入口角色

### 监管角色

- `106` 看人社合规闭环
- `107` 看应急风险治理闭环
- `108/109` 以只读分析视图为主

## 6. 研发分工建议

### 前端

- 按门户维护 `views/ygb` 和 `views/azb`
- 共用 API 目录
- 共用基础组件，少共用页面

### 后端

- 共表共 service
- 门户差异优先做汇总接口，不复制 CRUD
- 继续沿用 `portal_scope` 进行菜单隔离

### 测试

- 同一角色双门户菜单差异验证
- 同一模块双门户按钮差异验证
- 同一数据双门户展示口径差异验证

## 7. 验收口径

1. `ygb` 与 `azb` 能在同一后台下稳定登录并独立展示菜单。
2. `azb` 不再存在核心高频包装页。
3. `ygb` 独占模块不会在 `azb` 中出现。
4. 共性模块后端不复制，但前端允许独立演进。
5. 驾驶舱、AI 报告、统计报表的门户口径不再混用。
6. 企业管理员、工地负责人、操作员、财务、监管员进入系统后，默认入口符合各自工作习惯。

## 8. 建议执行顺序

1. 先补安责保驾驶舱与治理页汇总接口
2. 再统一角色矩阵和按钮边界
3. 再重做双门户首页和快捷入口
4. 最后清理剩余共享页的门户感知文案

这个顺序的原因很直接：

- 包装页已经清理完成，门户分离基础已具备
- 先补汇总接口，页面才能不拼数据
- 再做首页和角色矩阵，避免反复返工
