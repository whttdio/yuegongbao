# 粤工保安责保双前端实施批次（当前仓库版）

日期：2026-06-05

## 1. 总体实施法

双前端继续统一按这一套工程法推进：

1. 先保留一套后台对象和状态机。
2. 对共性模块抽共享组合层。
3. `ygb` 和 `azb` 只保留各自模板壳和角色动作。
4. 每完成一批都跑双构建。

## 3. 下一批实施顺序

### P2 高重叠治理模块

目标：

把“同一对象、两套监管口径”的模块继续收口成共享逻辑 + 双门户语义。

模块顺序：

1. `injuryEvent`
2. `preventionProject`
3. `preventionFund`
4. `enterprise`
5. `person`

每个模块统一交付：

- `useXxxPage.js`
- `views/ygb/xxx/index.vue`
- `views/azb/xxx/index.vue`
- 只读角色动作收口
- 双构建通过

### P3 治理入口模块

目标：

把安责保真正做成治理工作台，而不是普通列表页。

模块顺序：

1. `warning`
2. `warningRule`
3. `device`
4. `cockpit`
5. `statReport`

每个模块必须补齐：

- 摘要卡
- 焦点队列
- 当前对象面板
- 推荐动作区
- 详情提示标签
- 角色差异动作集

### P4 评分解释接入

目标：

把 `530.1` 业务事实接到 `6.1` 评分解释，不再停留在静态列表和报表页面。

后台补充能力：

- 评分维度配置
- 得分点配置
- 权重配置
- 月度聚合
- 企业评分快照
- 区域评分快照
- 门户口径解释聚合

前端输出方向：

- `ygb` 解释办理、整改、归档价值
- `azb` 解释风险、治理、处置价值

## 4. 页面统一标准

以后凡是共享模块改造，页面必须同时具备：

- 首屏摘要卡
- 焦点队列
- 当前选中对象摘要
- 推荐动作
- 详情提示标签
- 错误角色只读收口

不满足这六项，不算完成“工作台化升级”。
