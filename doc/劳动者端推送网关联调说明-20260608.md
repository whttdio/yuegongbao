# 劳动者端推送网关联调说明

## 1. 当前实现范围

当前仓库中，劳动者端推送链已具备以下能力：

- APP 登录后上报 `pushClientId / notificationPermission / pushPlatform`
- 后端保存当前劳动者推送注册信息
- 站内通知详情支持按 `jumpPath / jumpQuery` 落页
- APP 支持 `uni.onPushMessage` 点击推送后落页
- 后端已新增“可配置推送网关发送服务”
- 设置页已提供“发送测试推送”入口
- 设置页已提供“推送本地快照”，可查看本地 `ClientId`、最近登记尝试、最近登记结果、待消费落页
- 设置页已提供“重新登记推送”入口，可在切环境、重登或真机排障时手动重试

当前还没有内嵌某一家厂商 SDK 服务端实现，后端通过“推送网关 HTTP 调用”对接外部发送服务。

## 3. sys_config 配置项

需要在数据库 `sys_config` 表中配置以下参数：

- `ygb.worker.push.gateway.enabled`
  - `true` 启用后端推送发送链
  - `false` 关闭发送链
- `ygb.worker.push.gateway.url`
  - 推送网关 `POST` 地址
- `ygb.worker.push.gateway.provider`
  - 提供方标识，默认 `custom`
- `ygb.worker.push.gateway.authToken`
  - 若网关要求 `Bearer Token`，则配置在这里

初始化 SQL 已补在：

- `sql/ygb_phase21_worker_push_registration.sql`

## 4. 后端发送请求体

后端会向推送网关发送 `application/json` 请求，默认结构如下：

```json
{
  "provider": "custom",
  "clientId": "cid-example-001",
  "title": "粤工保劳动者端测试推送",
  "content": "服务端推送发送链已触发，请点击消息验证 APP 落页是否正确。",
  "payload": {
    "jumpPath": "/pages/notice/list",
    "jumpQuery": {
      "from": "push",
      "scene": "test"
    },
    "actionLabel": "查看通知",
    "sourceLabel": "服务端测试推送"
  },
  "metadata": {
    "userId": 10001,
    "userName": "worker01",
    "personId": 20001,
    "personName": "张三",
    "pushPlatform": "android",
    "notificationPermission": "authorized",
    "notifyEnabled": true,
    "source": "worker-settings-push-test"
  }
}
```

## 5. 网关返回判定规则

当前后端对以下返回视为成功：

- `{"success": true}`
- `{"code": "200"}`
- `{"code": "0"}`
- `{"code": "OK"}`
- `{"status": "success"}`
- `{"status": "ok"}`
- `{"status": "accepted"}`

如果网关返回空字符串、网络异常，或返回 `msg/message/error` 指示失败，后端会抛错并返回到前端设置页。

## 6. 联调步骤

### 6.1 数据库准备

1. 执行：
   - `sql/ygb_phase21_worker_push_registration.sql`
2. 检查 `ygb_worker_setting` 是否已包含：
   - `push_client_id`
   - `notification_permission`
   - `push_platform`
3. 检查 `sys_config` 是否已包含：
   - `ygb.worker.push.gateway.enabled`
   - `ygb.worker.push.gateway.url`
   - `ygb.worker.push.gateway.provider`
   - `ygb.worker.push.gateway.authToken`

### 6.2 网关准备

1. 准备一个可接收 `POST application/json` 的推送网关
2. 网关内部自行对接实际厂商，例如：
   - UniPush
   - 个推
   - 其他企业内部推送代理
3. 将网关地址写入：
   - `ygb.worker.push.gateway.url`
4. 启用发送链：
   - `ygb.worker.push.gateway.enabled=true`

### 6.3 APP 侧准备

1. 用真机登录劳动者端 APP
2. 在“设置 -> 接口环境”确认当前后端地址正确
3. 如切换过接口环境，建议重新登录一次
4. 登录后确认 `pushClientId` 已完成上报
5. 在“设置”页确认：
   - 业务通知偏好已开启
   - 系统通知权限为已授权

### 6.4 发送测试推送

1. 进入劳动者端“设置”页
2. 点击：
   - `发送测试推送`
3. 前端会调用：
   - `POST /app/worker/settings/push-test`
4. 后端会读取当前用户 `push_client_id`，构造默认测试 payload 并调用外部网关

## 7. 验收口径

### 7.1 后端验收

- `POST /app/worker/settings/push-test` 能正常返回
- 返回中可看到：
  - `gatewayUrl`
  - `provider`
  - `requestBody`
  - `responseBody`

### 7.2 客户端验收

- APP 真机收到测试推送
- 点击推送后能打开目标页
- 若未登录点击推送：
  - 先跳登录页
  - 登录成功后继续落到目标页
- 设置页“推送本地快照”能看到最近登记尝试时间、本地 `ClientId` 和待消费落页

### 7.3 跳转结构验收

- `payload.jumpPath` 被正确识别
- `payload.jumpQuery` 被正确透传
- `actionLabel / sourceLabel` 与通知详情页展示口径一致

## 8. 常见问题

### 8.1 点击“发送测试推送”直接报错“未启用”

原因：

- `ygb.worker.push.gateway.enabled` 仍为 `false`

### 8.2 点击“发送测试推送”报错“当前账号尚未完成推送注册”

原因：

- 当前劳动者账号还没有 `push_client_id`
- 需要真机登录 APP，并完成 push 注册上报
- 可先在设置页查看“推送本地快照”
  - 若 `ClientId` 为空，优先排查原生推送能力或真机运行环境
  - 若 `ClientId` 已有但最近登记结果失败，可点击“重新登记推送”并核对接口环境

### 8.3 后端返回成功，但手机没收到

优先排查：

- 手机系统通知权限是否开启
- APP 原生推送模块是否配置完整
- 网关是否真的调用到了第三方厂商
- 第三方厂商是否接受了 `clientId`

### 8.4 收到推送但点击不落页

优先排查：

- `payload.jumpPath` 是否为 `/pages/**`
- `payload.jumpQuery` 是否为对象或合法查询字符串
- APP 是否为最新包，包含 `worker-jump.js` 和 `uni.onPushMessage` 逻辑

## 9. 当前限制

- 目前后端只是“通用推送网关调用器”，不是厂商 SDK 直连实现
- 是否真实送达，仍取决于外部网关和第三方推送服务
- 当前只补到了“测试发送入口”，还没有和投诉结果、工资发放、培训提醒等真实业务事件自动联动
- 还缺真机联调记录和环境级验收截图

## 10. 结论

当前仓库已经具备：

- 推送注册
- 推送 payload 统一结构
- 客户端点击落页
- 服务端测试发送入口
- 网关配置口径

后续要完成真正的端到端闭环，只差两件事：

1. 配置真实推送网关
2. 做一轮真机联调验收
