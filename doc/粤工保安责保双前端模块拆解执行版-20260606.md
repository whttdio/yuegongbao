# 粤工保安责保双前端模块拆解执行版

日期：2026-06-06

## 1. 定案结论

当前系统应固定为以下长期结构：

- 一套后台
- 两个前端门户
- 两套登录页
- 两套首页工作台
- 一套企业/人员/预警/AI/设备/高处作业主数据
- 一套统一权限底座
- 一套统一业务接口，按门户和角色控制显示、入口、摘要和动作

这不是“同一个系统换两个标题”，而是：

- `ygb` 负责企业办理、人社监管、财务整改、月度归档
- `azb` 负责应急监管、安责险协同、设备治理、现场风险处置
- 后台只保留一套对象和一套状态机
- 前端按不同监管语义重排首页、菜单、详情重点和推荐动作

结合当前仓库代码，以上结构已经有基础实现，不应回退为单前端。

## 2. 当前仓库已具备的双门户基础

以下能力已经落地：

- 双登录入口
  - `yuegongbao-ui/src/router/index.js`
  - 路径已区分 `login/ygb` 与 `login/azb`
- 门户配置与品牌壳
  - `yuegongbao-ui/src/config/portal.js`
  - `yuegongbao-ui/src/utils/portal.js`
- 门户菜单与权限过滤
  - `yuegongbao-ui/src/permission.js`
  - `yuegongbao-ui/src/store/modules/permission.js`
- 双门户首页工作台脚本
  - `yuegongbao-ui/src/views/index.vue`
  - `yuegongbao-ui/src/views/homeWorkbenchConfig.js`
- 双外壳目录
  - `yuegongbao-ui/src/views/ygb`
  - `yuegongbao-ui/src/views/azb`
- 共享工作台跳转上下文
  - `yuegongbao-ui/src/utils/workbenchLink.js`

结论很明确：当前阶段不是“要不要双前端”，而是“哪些模块继续共逻辑双外壳，哪些模块只在 ygb 完整承载，哪些模块在 azb 强化治理表达”。

## 3. 总体拆解原则

### 3.1 后台必须共用的边界

以下对象必须保持单源，不允许按门户复制第二套表或第二套接口主链：

- 企业
- 人员
- 角色与菜单
- 合同
- 考勤
- 工资
- 社保
- 税务
- 预警与预警规则
- 设备
- 安责险保单
- 事故预防项目
- 事故预防资金
- 高处作业申报报备
- 工伤事件
- AI 原始事件、AI 报告、AI 配置
- 信用评分底数
- 统计报表底数
- 首页工作台聚合底数

### 3.2 前端必须分开的边界

以下内容必须按 `ygb/azb` 分开表达：

- 登录页品牌与文案
- 首页工作台
- 默认模块入口顺序
- 模块首屏摘要
- 焦点队列
- 详情页强调字段
- 推荐动作顺序
- 报表解释口径
- 驾驶舱指标排序

### 3.3 禁止做法

- 为 `azb` 复制第二套企业、人员、预警、设备、高处作业表
- 为 `azb` 再造第二套安责险、资金池、AI 报告接口主链
- 把 `ygb` 页面复制一份到 `azb` 只改标题
- 把门户差异继续堆回后端 if/else，导致接口口径分叉

## 4. 模块归属定案

### 4.1 只在 `ygb` 完整承载的办理链模块

这些模块属于企业办理和财务整改主链，不建议在 `azb` 再做完整录入页：

- `contract`
- `attendanceRaw`
- `attendanceMonthly`
- `salaryBatch`
- `salaryDetail`
- `socialPayment`
- `socialBaseCompare`
- `taxCompare`
- `employmentRatio`
- `fakeOutsourcing`
- `newformWorker`
- `occupationMonitor`

`azb` 如果需要使用这些结果，只允许引用摘要、风险结论和评分解释，不再承接原始办理流程。

### 4.2 共后台 + 双外壳承载模块

这些模块后端必须共用，但前端必须分成 `ygb` 与 `azb` 两套视图：

- `home`
- `cockpit`
- `enterprise`
- `person`
- `warning`
- `warningRule`
- `device`
- `aqInsurance`
- `preventionFund`
- `preventionProject`
- `injuryEvent`
- `heightWorkReport`
- `aiReport`
- `aiReportConfig`
- `creditScore`
- `statReport`
- `uninsuredList`

落地方式固定为：

- 共享逻辑在 `src/views/<module>/useXxxPage.js` 或共享 API
- 粤工保外壳在 `src/views/ygb/<module>/index.vue`
- 安责保外壳在 `src/views/azb/<module>/index.vue`

### 4.3 `azb` 主责强化模块

以下模块虽然共后台，但页面语义必须明显偏向 `azb`：

- `aqInsurance`
- `device`
- `warning`
- `heightWorkReport`
- `aiReport`
- `creditScore`
- `statReport`
- `preventionFund`
- `preventionProject`
- `injuryEvent`

这些模块在 `azb` 首屏必须突出：

- 当前风险等级
- 重点对象队列
- 在途处置
- 超时未闭环
- 区域分布
- 治理成效

### 4.4 `ygb` 主责强化模块

以下模块在 `ygb` 首屏必须突出：

- 办理状态
- 财务闭环
- 整改对象
- 月度归档
- 企业高频入口
- 监管抽查入口

尤其要围绕以下链路组织：

- 合同备案 -> 考勤 -> 工资 -> 社保/税务 -> 预警整改
- 企业录入 -> 高处作业报备 -> 作业结束 -> 凭证留痕

## 5. 角色与门户归属

固定角色归属如下：

| 角色 | 默认门户 | 长期定位 |
| --- | --- | --- |
| `104 ygb_enterprise_admin` | `ygb` | 企业管理员 |
| `105 ygb_enterprise_operator` | `ygb` | 企业经办/操作员 |
| `106 ygb_hrss_supervisor` | `ygb` | 人社监管员 |
| `107 ygb_emergency_supervisor` | `azb` | 应急监管员 |
| `108 ygb_insurer` | `azb` | 保险公司 |
| `109 ygb_bank` | `azb` | 银行 |

补充规则：

- 企业角色可以访问双门户，但默认入口仍是 `ygb`
- 企业角色进入 `azb` 后，应切换成“现场治理视角”，而不是再看到工资合同主链
- `108/109` 保持只读协同，只保留摘要、详情、导出、报表

## 6. 两个门户的业务语义

### 6.1 `ygb`

主要服务用户：

- 工地负责人
- 操作员
- 财务经办
- 人社监管员

### 6.2 `azb`

`azb` 应围绕以下动作组织页面：

- 风险
- 处置
- 时效
- 在途
- 重点对象
- 区域治理

主要服务用户：

- 应急监管员

- 银行
- 企业现场治理角色

## 7. 模块级拆解建议

### 7.1 首页与工作台

- `ygb` 首页先放合同、考勤、工资、社保、高处作业、预警整改
- `azb` 首页先放驾驶舱、预警中心、设备、高处作业、安责险、资金池
- 同一对象从首页进入目标页时，要保留筛选上下文

当前仓库已经在这条线上落地：

- `index.vue` 首页队列跳转
- `workbenchLink.js` 路由上下文
- 多个台账页支持来源条件承接与清空

### 7.2 企业与人员

- 后台完全共用
- `ygb` 强调用工关系、参保、工资、合同
- `azb` 强调现场治理、设备授权、高危作业、预警关联

### 7.3 预警中心

- 共用预警对象、规则、工单
- `ygb` 按合规整改链组织
- `azb` 按风险压降和处置时效组织

### 7.4 设备与技术防范

- 后台共设备档案、授权、事件
- `ygb` 只承接必要联动信息
- `azb` 作为主治理页面，突出在线率、离线时长、锁机、围栏、AI 事件

### 7.5 高处作业

- 一套报备表、一套人员明细、一套证书 Stub、一套凭证结构
- `ygb` 偏企业现场办理
- `azb` 偏监管在途治理

### 7.6 安责险、资金池、信用、统计

- `aqInsurance/preventionFund/creditScore/statReport` 后台统一
- `azb` 为主语义承载端
- `ygb` 只保留与企业、工伤预防、扩面减损有直接关系的解释口径

## 8. 与 530.1 和 6.1 的挂接方式

### 8.1 530.1 对应 `ygb`

530.1 的主价值链应落到 `ygb`：

- 劳务合规
- 工资发放
- 社保税务比对
- 用工比例与假外包识别
- 工伤预防
- 扩面减损

### 8.2 6.1 对应 `azb`

6.1 的主解释链应落到 `azb`：

- 安责险覆盖
- 设备安全
- 技术防范
- AI 风险识别
- 隐患整改
- 区域治理成效

### 8.3 挂接原则

- 同一企业在 `ygb` 与 `azb` 共用同一底数
- 两端只改变解释顺序、摘要视角、推荐动作
- 评分权重、阈值、得分点应走配置，不写死在页面

## 9. 对研发的直接要求

后续所有双前端改造必须遵守：

1. 后台坚持单套对象、单套状态机、单套核心接口。
2. 门户差异优先落在前端壳层，不回灌成后台双分支。
3. 共性模块一律走“共享逻辑 + 双外壳”。
4. 企业办理主链收口到 `ygb`。
5. 风险治理主链强化到 `azb`。
6. 同一对象允许双视图，不允许双建模。

- 后续研发评审口径
